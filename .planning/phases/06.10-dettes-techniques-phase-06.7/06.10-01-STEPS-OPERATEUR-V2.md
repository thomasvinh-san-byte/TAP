# Steps opérateur Wave 1 Tentative 2 — config legacy Vercel

Après merge de la PR `feat/06.10-01-vercel-legacy-builds`, suivre ces 4 étapes côté Vercel UI.

## Step 1 — Attendre le déploiement preview

Compter ~3-5 min après merge. Trouver l'URL preview dans le dashboard Vercel → onglet `Deployments` → cliquer sur le dernier déploiement → champ `Domains` en haut.

**Signal d'alerte précoce** : si le build affiche immédiatement un message du type `Function pattern doesn't match` (rejouerait Tentative 1) ou `Both 'builds' and 'functions' detected` (config cumulative) → **abandon Tentative 2 sans attendre**. Lire la section Step 4 pour basculer TypeScript/WASM.

## Step 2 — Tester l'endpoint `/health`

```bash
curl -I "https://<preview-url>/api/solver/health"
```

- **HTTP 200** → ✓ Tentative 2 réussit. Passer à Step 3.
- **HTTP 404** → ✗ la route Vercel ne route pas vers la fonction Python. Lire les Build Logs (`Deployments` → dernier → onglet `Building` ou `Logs`) pour comprendre. Si la fonction n'apparaît pas dans `Functions` tab, le builder `@vercel/python` n'a pas traité le fichier.
- **HTTP 500** → ✗ la fonction Python est trouvée mais crashe au runtime. Lire les Runtime Logs (`Deployments` → dernier → onglet `Functions` → `py/solver/index.py` → `Runtime Logs`).

## Step 3 — Si OK, walkthrough OR-Tools réel

1. Vercel UI → `Settings` → `Environment Variables` → trouver `OPTIMIZER_USE_MOCK` :
   - Modifier la valeur **Preview** : `true` → `false`.
   - **NE PAS toucher** la valeur Production (laisser à `true`).
2. `Deployments` → dernier preview → menu `…` → `Redeploy`. Attendre ~2 min.
3. Recharger `/cockpit/optimisation`, lancer le calcul sur une journée avec courses géocodées (sinon utiliser le seed ad hoc `seed-courses-pour-optimiseur.sql`).
4. Vérifier que la réponse est différente du mock :
   - Le `motif` doit être plus détaillé que le déterministe du mock (« Courses proches dans la même zone, fenêtres horaires compatibles »).
   - Le `gain_km_a_vide` doit être variable selon les courses (mock = 4.2 km fixe).
   - Le temps de réponse doit être 1-3 s (mock = instantané).

## Step 4 — Si critère d'abandon 2 h atteint sans succès

1. Inscrire le symptôme exact dans le tableau « Tentative 2 » à la fin de `.planning/phases/06.10-dettes-techniques-phase-06.7/06.10-01-PLAN.md` : HTTP code + premières lignes du body + extrait des Build/Runtime Logs Vercel si lisibles.
2. Demander à Claude-chat le prompt pour **Phase 06.11 — Refactor solveur TypeScript/WASM**. Les options sont déjà cadrées dans l'enquête post-échec (`docs/dette-technique/2026-06-01-enquete-post-echec-wave1.md`) :
   - Option A : `reinterpretcat/vrp` Rust + WASM (qualité proche OR-Tools).
   - Option B : refactor TS heuristique custom (qualité moindre, stack 100 % TS).
3. **Render reste exclu** par directive dirigeant — ne pas le proposer ni le considérer.
