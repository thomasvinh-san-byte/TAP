# Steps opérateur Wave 1 — tentative Vercel Python /py/

Après merge de la PR `feat/06.10-01-vercel-python-py-relocate`, suivre ces 5 étapes côté Vercel UI.

## Step 1 — Attendre le déploiement preview

- Aller sur `vercel.com/<account>/<projet-web>/deployments`.
- Le déploiement preview correspondant au merge est visible en tête de liste (~3-5 min pour build + deploy).
- Récupérer l'URL preview (`https://<projet-web>-<hash>.vercel.app`).

## Step 2 — Tester l'endpoint /health

```bash
curl -I "https://<preview>/api/solver/health"
```

- **HTTP 200** → ✓ le rewrite Next.js fonctionne, Vercel route bien vers la fonction Python. Continuer Step 3.
- **HTTP 404** → ✗ la fonction Python n'est pas trouvée. Aller dans le dashboard `Deployments` → dernier déploiement → onglet `Functions` : la fonction `py/solver/index.py` doit apparaître. Si elle n'y est pas, lire les Build Logs pour comprendre.
- **HTTP 500** → ✗ erreur au runtime Python. Onglet `Functions` → fonction `py/solver/index.py` → `Runtime Logs` pour lire la stack trace.

## Step 3 — Si OK : basculer `OPTIMIZER_USE_MOCK=false` PREVIEW UNIQUEMENT

- Dashboard Vercel → projet `apps/web` → `Settings` → `Environment Variables`.
- Trouver `OPTIMIZER_USE_MOCK` (devrait exister à `true` sur Production et Preview).
- Éditer la valeur Preview : passer à `false`. **Ne PAS toucher Production** (le mock reste actif en prod).
- Cliquer `Save`.
- Aller sur `Deployments` → dernier preview → `Redeploy` (icône `…` en haut à droite).
- Attendre redéploiement (~2 min).

## Step 4 — Walkthrough optimisation

- Ouvrir `https://<preview>/cockpit/optimisation` avec un compte régulateur ou dirigeant connecté.
- Cliquer « Lancer le calcul » sur la journée du jour (ou une date avec courses géocodées — sinon utiliser le seed ad hoc `seed-courses-pour-optimiseur.sql`).
- Vérifier la réponse :
  - Le `motif` doit être plus détaillé que celui du mock (mock renvoie « Courses proches dans la même zone, fenêtres horaires compatibles » de façon déterministe).
  - Le `gain_km_a_vide` doit être un calcul Haversine × correction réaliste (le mock renvoie 4.2 km fixe).
  - Le temps de réponse doit être 1-3 s (mock = instantané).
- Si la réponse est cohérente avec OR-Tools, Wave 1 est **un succès**.

## Step 5 — Si NOK : tracer dans le PLAN et déclencher Wave 1bis

- Inscrire dans le tableau « Tracking d'exécution » à la fin de `.planning/phases/06.10-dettes-techniques-phase-06.7/06.10-01-PLAN.md` : durée écoulée + symptôme exact (HTTP code + premières lignes du body + extrait des Build/Runtime Logs Vercel si lisibles).
- Si palier 4 h atteint sans succès : déclencher Wave 1bis via un nouveau prompt Claude Code « Wave 1bis Phase 06.10 — bascule Render Starter Docker pour le solveur OR-Tools per ADR-009 ».
- Si étape intermédiaire bloque (logs inaccessibles, erreur non comprise après 2 h d'analyse), demander à Claude-chat un diagnostic ciblé avant d'attendre les 4 h.
