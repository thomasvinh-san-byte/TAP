# Plan 06.10-02 — Wave 2 : Pipeline geocoding au moment création course (D2)

## Goal

Persister automatiquement `pickup_lat/lng/citycode` + `dropoff_lat/lng/citycode` à la création d'une course via UI, en réutilisant les coordonnées déjà disponibles dans le `onChange` de l'autocomplete BAN/Géoplateforme. Élimine le besoin du seed ad hoc `seed-courses-pour-optimiseur.sql` et débloque la validation de l'optimiseur sur des données réelles.

## Pré-requis

- Wave 1 terminée (Vercel `/py/` OK ou bascule Render OK) ; ou exécution parallèle si audit Wave 2 révèle un cas A simple.
- Pas de modification du schéma `rides` (colonnes `pickup_lat`, `pickup_lng`, `pickup_citycode`, `dropoff_lat`, `dropoff_lng`, `dropoff_citycode` existent déjà depuis migration Phase 04.7).

### Pourquoi le diagnostic « 0/25 courses ont coords » ?

Le pipeline UI → DB est correct. **Les 25 courses observées sans coords viennent du seed démo** `supabase/seed.demo.sql` qui insère des courses avec uniquement `pickup_address` et `dropoff_address`, sans les 6 colonnes lat/lng/citycode.

```bash
grep "pickup_lat" supabase/seed.demo.sql    # 0 occurrence
grep "pickup_address" supabase/seed.demo.sql  # 8 occurrences (3 INSERT INTO rides + ON CONFLICT DO UPDATE)
```

Une course créée via UI (avec `AddressPickerField` + sélection d'une suggestion BAN) aura ses 6 colonnes coords persistées correctement. Une course du seed démo n'en a pas — d'où l'exclusion par l'optimiseur (`reason='no_coordinates'`).

### Fix appliqué dans cette PR (T5-A — test de non-régression)

Pas de modification de `createRideAction` ni d'`AddressPickerField` — le pipeline marche déjà.

**Ajout de 3 tests Vitest** dans `packages/shared/src/validators/__tests__/ride.test.ts` qui **scellent le contrat coords** côté schema zod :

- Test 11 : les 6 colonnes coords sont préservées après `parse`. Si ce test casse, le pipeline UI → DB est rompu (quelqu'un a retiré les colonnes du schema, et `createRideAction` ne les spread plus).
- Test 12 : `null` sur les 6 colonnes est accepté (fallback D-ADDR-04 saisie libre sans autocomplete BAN).
- Test 13 : `lat` hors [-90, 90] ou `lng` hors [-180, 180] est rejeté.

Vitest : **83/83 verts** (passe de 80 à 83). Aucune régression.

### T7 (seed démo) — non traité dans cette PR

Le seed `supabase/seed.demo.sql` reste à patcher pour ajouter les 6 colonnes coords aux courses démos. **Reporté à une PR séparée** pour ne pas mélanger les concerns (cette PR scelle le pipeline applicatif ; le seed est une dette de fixtures démo distincte).

Une course créée via UI **dès aujourd'hui** sur preview Vercel (avec Wave 1 mergée) aura ses coords correctement persistées. C'est ce que le walkthrough opérateur doit vérifier.
