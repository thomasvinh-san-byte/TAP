## Décisions fermées

check (... in ('warn', 'block'))` sur `organizations`. Pas de table

### D-02 — Helper niveau entité (`@tap/shared`)

- **8 tests Vitest verts** — module pur, partagé serveur + client.

### D-03 — Assignation manuelle (assign-modal)

- Charge `mode + lookup` via `getAssignmentComplianceContextAction`
  (1 round-trip, useQuery).
- **Badge « Non conforme »** (icône `AlertCircle` + texte, WCAG 1.4.1)
  sur les chauffeurs avec ≥ 1 échéance expirée.
- **Mode `warn`** (défaut) : chauffeur reste sélectionnable, panneau
  d'avertissement affiché (« assignation sous votre responsabilité »),
  toast `warning` au succès.
- **Mode `block`** : ligne **désactivée** (`disabled`, `aria-disabled`,
  `cursor-not-allowed`, opacité 60), submit refusé client-side
  + revérif serveur (defense in depth).
- **Server Action `assignRideAction`** appelle `checkAssignmentCompliance`
  AVANT l'UPDATE — refuse en mode `block` quel que soit le client.

### D-04 — Assignation auto (optimiseur)

Route `POST /api/optimizer` :
- Lit `compliance_blocking_mode` + lookup véhicules.
- **Mode `warn`** : tous les véhicules vont au solveur ; les non
  conformes sont signalés via le nouveau champ
  `proposal.complianceWarnings: { vehicle_id, label, blocked: false }[]`.
- **Mode `block`** : véhicules non conformes filtrés du pool envoyé
  au solveur ET inscrits dans `complianceWarnings` avec
  `blocked: true`.
- L'UI `optimization-shell` affiche un panneau dédié
  (`<ComplianceOptimizerWarnings>`) en haut de la proposition avec
  liste + lien `/admin/conformite`.

Extension de `OptimizationProposal` (`packages/optimizer-client`) :
ajout d'un champ optionnel `complianceWarnings`, rétro-compatible
(absent côté V1 → panneau omis).

### D-05 — Lecture du mode

`getComplianceBlockingMode()` (helper `_lib/compliance-planning.ts`,
`'server-only'`) — source unique côté serveur. Fail-open : défaut
`'warn'` si lecture échoue (pas de blocage du travail sur erreur infra).

### D-06 — Réglage UI dirigeant

`<BlockingModeControl>` dans `/admin/conformite` (réservé dirigeant) :
SegmentedControl Avertir/Bloquer, état initial fetché RSC + persistance
via `updateComplianceBlockingModeAction` (DEC-041 row-count check sur
UPDATE). Texte explicatif sobre.

### D-07 — Périmètre

Contrôle à la planification UNIQUEMENT. Pas de nouveau type d'échéance,
pas d'email/push, pas de cron. Réglage GLOBAL (pas par type).
