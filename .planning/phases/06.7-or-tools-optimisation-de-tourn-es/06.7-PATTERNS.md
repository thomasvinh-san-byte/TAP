### `services/optimizer/` — Python layer (no in-repo analog)

There is no existing Python code in this monorepo. The `services/` directory does not yet exist on disk. The following documents the conventions the new directory must follow, drawn from the project's established architecture patterns.

**Monorepo placement:** `services/optimizer/` sits at the repository root alongside `apps/` and `packages/`. It is a standalone Python container, not a Node workspace. It must NOT be listed in `pnpm-workspace.yaml`.

**Directory skeleton to create:**

```
services/
└── optimizer/
    ├── Dockerfile
    ├── requirements.txt          # runtime deps
    ├── requirements-dev.txt      # pytest + httpx
    ├── pytest.ini                # testpaths = tests
    ├── main.py                   # FastAPI app + /solve endpoint
    ├── solver.py                 # OR-Tools PDPTW logic (pure function)
    ├── models.py                 # Pydantic SolveRequest / SolveResponse
    ├── haversine.py              # distance matrix (~10 lines)
    └── tests/
        ├── conftest.py           # httpx AsyncClient fixture
        ├── test_solver.py        # unit tests on solver.py
        └── test_api.py           # integration tests on /solve endpoint
```

**Python file naming convention:** `snake_case.py` — consistent with Python standard library and FastAPI documentation conventions.

**TypeScript file naming convention for reference:** `kebab-case.ts` (from CLAUDE.md §7).

**Note on `haversine.py`:** the TypeScript analog is the private `haversineKm` function in `packages/pricing/src/compute-cgss-short-trip.ts` (lines 65–73). It is NOT exported and cannot be imported from Python. Recalculate in Python as ~10 lines of `math` stdlib — no third-party library required.
