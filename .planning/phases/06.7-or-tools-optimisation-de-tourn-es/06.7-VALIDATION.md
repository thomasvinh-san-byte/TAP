### OPTI-03 — Mutualisation de courses (groupement multi-patients)
- **Test type:** pytest (Wave 1, livrée)
- **Files:**
  - `services/optimizer/tests/test_solver.py::test_groupement_simple` (Wave 1 — vert)
  - `services/optimizer/tests/test_solver.py::test_incompatible_windows` (Wave 1 — vert)
  - `services/optimizer/tests/test_solver.py::test_capacity_respected` (Wave 1 — vert)
- **Verifies:** 2 courses compatibles (même destination, fenêtres horaires chevauchantes, capacité véhicule suffisante) → le solveur retourne 1 groupement avec les deux `ride_ids` ; 2 courses dont les fenêtres horaires sont disjointes → le solveur retourne 0 groupement et les 2 courses sont dans `rides_non_groupees_ids` ; contrainte de capacité véhicule respectée (3 courses simultanées sur véhicule 1 place → le solveur ne crashe pas, comptabilise les 3 courses dans la sortie).

### OPTI-04 — Mutualisation temporelle (intercalation dans temps d'attente)
- **Test type:** pytest (Wave 1, livrée)
- **Files:**
  - `services/optimizer/tests/test_solver.py::test_mutualisation_temporelle` (Wave 1 — vert)
- **Verifies:** quand une course B s'insère dans le temps mort entre `pickup` et `dropoff` d'une course A, le solveur produit un groupement ordonné cohérent (séquence `pickup_A → pickup_B → dropoff_B → dropoff_A` ou équivalent admissible). L'ordre des étapes est exposé dans le champ `order` du groupement (4 étapes pour ce scénario).
