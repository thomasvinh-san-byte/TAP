## Phase Boundary

sans créer de divergence entre sources de vérité. La cible :
`apps/web/src/styles/tokens.json` (format DTCG 2025.10) devient la **seule

- 3 sites de couleurs hex en dur (élargi par l'analyse vs RESEARCH §0) :

Estimation indicative 5-8 h, à raffiner en plan.

## Implementation Decisions

### A — Architecture DTCG du dark dans tokens.json

- **D-01 :** Architecture **Token Sets** : `apps/web/src/styles/tokens.json`
  reste la base light. Nouveau `apps/web/src/styles/tokens.dark.json`
  override **uniquement les 12 couleurs chromatiques**. Les 45 invariants
  (spacing, typo, radius, shadow, motion, touchTarget) ne sont JAMAIS
  dupliqués. Style Dictionary compose les deux sources pour produire le bloc
  `:root` (light) et `[data-theme='dark']` dans `globals.css`. Rationale :
  pattern standard DTCG 2025.10 + Style Dictionary, multi-thème-friendly
  (extensible vers un futur `tokens.high-contrast.json` pour PWA chauffeur
  plein soleil mentionné CLAUDE.md §5).

- **D-02 :** Les **3 couleurs sans dark documenté** reçoivent une valeur dark
  **explicite** dans `tokens.dark.json` (pas d'héritage implicite cross-theme,
  règle « jamais d'invisible-on-dark silencieux ») :
  - `color.text.onAction` : valeur dark explicite (à figer en plan).
  - `color.action.focusRing` : aligné sur `--primary` dark (`hsl(217 91% 60%)`).
  - `color.border.input` : aligné sur `--border` dark (`hsl(217 33% 22%)`,
    cohérent avec `globals.css:50` actuel).

### B — Pipeline de génération Style Dictionary

- **D-03 :** `style-dictionary` v4 ajouté en **devDependency racine** du
  monorepo (pas dans `apps/web` seul) pour permettre le partage futur avec
  `apps/mobile`/`apps/admin`/`packages/ui`. Aucune dépendance runtime —
  Style Dictionary n'est consommé qu'au build.

- **D-04 :** Script `tokens:build` dans `apps/web/package.json`, branché en
  **`prebuild`** (et exposé en commande manuelle). Garantit que toute
  préview Vercel compile les tokens sans intervention humaine. Ne pas
  brancher en `postinstall` (ralentit CI cold-start) ni en `prepare` Husky
  (alourdit chaque commit, complique les rebases).

- **D-05 :** Style Dictionary génère **2 outputs** :
  - `apps/web/src/app/globals.css` (CSS vars light + bloc `[data-theme='dark']`)
    avec le format `css/variables` (ou `customFormat` minimal si le built-in
    v4 ne supporte pas les deux sélecteurs nativement — à confirmer cf.
    `<deferred>` D-08).
  - `apps/web/src/styles/tokens.generated.ts` (format `javascript/es6`) pour
    les contextes hors-DOM (PDF, `themeColor` PWA). Export TypeScript typé.

- **D-06 :** `tailwind.config.ts` **n'est PAS régénéré** par Style Dictionary.
  Il reste consommateur statique des CSS vars produites. Régénérer la
  config Tailwind apporterait zéro valeur et casserait le pattern alpha
  qu'on introduit en D-07.

### C — Correction du pattern alpha Tailwind

- **D-07 :** Migrer les **16 occurrences** de `hsl(var(--x))` en
  `hsl(var(--x) / <alpha-value>)` **uniquement dans
  `apps/web/tailwind.config.ts:17-42`**. Le placeholder `<alpha-value>` est
  interprété par le compilateur Tailwind exclusivement. **Ne pas toucher**
  `globals.css` (overrides react-datepicker, font-feature-settings)
  ni `(driver)/layout.tsx:54` (CSS inline) — l'ajout du placeholder y
  produirait une couleur invalide côté navigateur.

### D — Migration des couleurs en dur (périmètre élargi)

- **D-08 :** Le périmètre RESEARCH §0 « 2 fichiers `.tsx` » est élargi à
  **3 sites** après vérification code :
  - `apps/web/src/lib/pdf/pdf-template.tsx:15-19` (5 hex).
  - `apps/web/src/app/api/admin/facturation/pdf/_components/facture-cgss-pdf.tsx:21-46`
    (5 hex).
  - `apps/web/src/app/layout.tsx:23` (`themeColor: '#0944a0'`, manifest PWA
    — non comptabilisé par RESEARCH).
  Les 3 sites importent **`tokens.generated.ts`** (produit par D-05) au
  lieu de hex en dur. Dérive vérifiée : `#1466DB` actuel dans pdf-template
  vs `hsl(217 92% 32%) ≈ #0944A0` dans tokens — la dérive est **déjà
  présente** avant 06.14. Migrer en 06.14 referme la promesse « tokens.json
  = source unique ».

### Claude's Discretion

- Architecture Token Sets (D-01) tranchée après lecture spec DTCG 2025.10 +
  doc Style Dictionary theming. Inscriptible en ADR si jugé structurant en
  plan-phase (à arbitrer : 1 décision design qui contraint toute migration
  multi-thème future).

## Existing Code Insights

### Reusable Assets

- `apps/web/src/styles/tokens.json` (Phase 06.13) — source DTCG 2025.10
  validée `jq empty`. Structure 7 groupes (color/spacing/radius/typography/
  shadow/motion/touchTarget). Aucune valeur dark exploitable (uniquement
  en prose dans `$description`) — c'est précisément ce que D-01/D-02
  corrigent.
- `apps/web/tailwind.config.ts` (lignes 10, 17-42) — déjà configuré
  `darkMode: ['class', '[data-theme="dark"]']` ; la cible Token Sets
  s'y mappe trivialement.
- `apps/web/src/app/globals.css:36` — sélecteur `[data-theme='dark']`
  déjà utilisé. Aucun refactor de selector.

### Established Patterns

- **NFR-003** (couleur jamais seule) : tous les patterns 06.11 (`KpiCard`,
  `EmptyState`, `RideBadge`, `SlaBadgesCard`, `HautsBadge`) doublent la
  couleur avec un texte/icône. La migration tokens ne touche pas à ce
  niveau — elle déplace la source des valeurs, pas la sémantique.
- **HSL components sans wrapper** : `globals.css` utilise déjà la syntaxe
  moderne `--primary: 217 92% 32%` (composantes HSL espacées, sans
  `hsl()`). C'est le prérequis pour `hsl(var(--x) / <alpha-value>)`
  (D-07).
- **Mode jour + nuit à parité** (CLAUDE.md § 1 pilier 2) — D-01 préserve.

### Integration Points

- **Vercel build** : `pnpm build` côté `apps/web` doit déclencher
  `tokens:build` avant Next.js compile. Vérifier que `cd.yml` n'override
  pas la chaîne. D-04 pré-suppose que `prebuild` npm est respecté par
  Turbo (à confirmer lecture `turbo.json`).
- **react-datepicker overrides** (`globals.css:115-193`) : référencent
  `--popover`, `--popover-foreground` — ces CSS vars n'existent pas dans
  `tokens.json` (Phase 06.13). Décider en plan-phase si elles sont
  ajoutées aux tokens ou laissées comme overrides locaux.
- **PWA chauffeur tint** (`--driver-surface`) : déjà dans `tokens.json`
  et `globals.css`, mais consommé en CSS inline dans
  `(driver)/layout.tsx:54`. Pas à migrer (consommation directe).
