# Plan 06.14-01 — Migration tokens.json → Tailwind config

## Goal

Brancher `tokens.json` comme **source de vérité unique** sur le code :
restructure en Token Sets (base + dark override), génération d'un fragment
CSS dédié + export JS via Style Dictionary v4, correction du pattern alpha
Tailwind, migration des 3 sites hex en dur, correction du bug latent
`--popover`/`--popover-foreground`. Reste Tailwind v3. Aucune dépendance
runtime. Aucune migration BDD.

Toutes les décisions sont fermées dans `06.14-CONTEXT.md` (D-01..D-11) —
ce plan ordonnance, il ne questionne pas.

## Pré-requis

- CONTEXT 06.14 lu (D-01..D-11, valeurs figées des 3 + 2 couleurs sans
  dark).
- RESEARCH 06.14 lu (§3 placeholder Tailwind, §5 R3 architecture dark).
- Doctrine 06.13 préservée (`docs/design-system/01-foundations.md` reste
  cohérente après génération — aucune valeur sémantique ne bouge).

## Tâches

### T1 — Restructurer les tokens (D-01, D-02, D-10)

Sortie : `apps/web/src/styles/tokens.json` (nettoyé) +
`apps/web/src/styles/tokens.dark.json` (nouveau).

- **T1.1** `tokens.json` : retirer les mentions « Sombre : … » dans les
  `$description` des 12 couleurs chromatiques + des 2 nouvelles popover
  (D-10). Les `$description` documentent la sémantique, pas les variantes —
  ces dernières sont portées par `tokens.dark.json`.
- **T1.2** `tokens.json` : ajouter les 2 nouveaux tokens light (D-10) :
  - `color.surface.popover` : `hsl(0 0% 100%)`
  - `color.text.onPopover` : `hsl(222 47% 11%)`
- **T1.3** Créer `tokens.dark.json` (override des 14 couleurs chromatiques
  uniquement, les 45 invariants NON dupliqués) :
  - 12 couleurs documentées : valeurs sombres extraites des `$description`
    (cf. `tokens.json` actuel) + 2 popover D-10 + valeurs figées pour les
    3 couleurs sans dark documenté (`text.onAction = hsl(222 47% 11%)`,
    `action.focusRing = hsl(217 91% 60%)`, `border.input = hsl(217 33% 22%)`).
  - Schéma `$schema` identique, structure miroir de `tokens.json` mais
    n'inclut QUE les nœuds chromatiques overridés.
- **T1.4** Valider `jq empty` sur les 2 fichiers. Compteur attendu : 14
  couleurs chromatiques avec dark + 45 invariants = 59 tokens (vs 57 en
  Phase 06.13 — +2 popover).

### T2 — Ajouter Style Dictionary v4 (D-03)

Sortie : `package.json` racine modifié, `pnpm-lock.yaml` mis à jour.

- **T2.1** `pnpm add -wD style-dictionary@^4` (ajout devDependency racine).
  Confirmer la version exacte (≥ 4.x) ; vérifier qu'aucun autre package du
  monorepo n'a déjà SD à une version différente.
- **T2.2** Vérifier que `pnpm install` ne casse pas la CI Vercel
  (compatible Node 20 — ESM-only, D-11 cible une config `.mjs`).

### T3 — Config Style Dictionary + génération du fragment CSS (D-05, D-09)

Sortie : `apps/web/style-dictionary.config.mjs`,
`apps/web/src/styles/tokens.generated.css` (généré, committé),
`apps/web/src/styles/tokens.generated.ts` (généré, committé).

- **T3.1** Écrire `apps/web/style-dictionary.config.mjs` :
  - `source`: `['src/styles/tokens.json']` pour le set light.
  - Set dark via plateforme dédiée ou via `include` du `tokens.dark.json`,
    selon ce que SD 4.x supporte. Cible : générer un fichier avec deux
    sélecteurs (`:root` light + `[data-theme='dark']` dark).
  - Plateformes : `web/css` (format `css/variables` ou `customFormat`
    minimal ≤ 30 lignes qui concatène les blocs `:root` + `[data-theme='dark']`
    si le built-in v4 ne sait pas émettre deux sélecteurs), `web/js`
    (format `javascript/es6` pour `tokens.generated.ts`).
- **T3.2** Générer une première fois localement (`pnpm --filter @tap/web
  tokens:build` après T4). Vérifier :
  - `tokens.generated.css` : commence par en-tête
    `/* GÉNÉRÉ par tokens:build — ne pas éditer */`, contient `:root { … }`
    suivi de `[data-theme='dark'] { … }`, expose toutes les 14 vars
    chromatiques + 45 vars invariantes.
  - `tokens.generated.ts` : export named TypeScript avec valeurs hex
    (les contextes PDF / `themeColor` PWA ont besoin de hex, pas HSL).
    Convertir HSL → hex via plateforme SD `transforms`.
- **T3.3** Lancer prettier sur les 2 outputs pour garantir
  `format:check` vert (D-11 garde-fou).

### T4 — Câbler `build` (D-11)

Sortie : `apps/web/package.json` modifié, `turbo.json` modifié.

- **T4.1** `apps/web/package.json` :
  - Ajouter `"tokens:build": "style-dictionary build --config style-dictionary.config.mjs"`.

- **T4.2** `turbo.json` : task `tokens:build` avec

- **T4.3** Vérifier `pnpm --filter @tap/web build` localement : tokens
  régénérés, Next.js compile, pas d'erreur d'import.
