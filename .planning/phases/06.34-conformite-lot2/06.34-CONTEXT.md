## Cadrage validé (rappel)

- **Q1 IN-APP uniquement** : cockpit (régulateur) + dashboard (dirigeant).
  Email/push = branchement d'infra REPOUSSÉ. La logique expose ses
  données pour qu'un canal externe futur les consomme sans refonte.
- **Q2 DÉRIVÉ** : statut/alerte calculés à la volée depuis
  `compliance_items` vs date du jour. PAS de table d'alertes
  stockées, pas d'accusé de lecture (une échéance reste visible tant
  qu'elle n'est pas réglée). Validé par RETEX secteur.
- **Cron pg_cron : pas nécessaire** au lot 2 (affichage dérivé suffit ;
  le cron servira au futur canal externe).

## Décisions fermées

### D-01 — Helper de sélection/tri pur (`@tap/shared`)

`packages/shared/src/utils/compliance-alerts.ts` :

- `selectComplianceAlerts(items, today?) → ComplianceAlert[]` :
  - Filtre : ne garde que `soon` (≤ 90 j) + `expired`.
  - Tri par urgence : `expired` d'abord (le plus passé en haut), puis
    `soon` ascendant (le plus proche en haut).
- `countComplianceAlerts(alerts) → { expired, soon, total }`.
- Module pur sans dépendance React/Supabase. Partagé par cockpit,
  dashboard et futur canal externe (email/push) sans refonte.
- **9 tests Vitest verts** (filtre + tri + borne 90 j + buckets).

### D-04 — Query serveur partagée (`_lib`)

`apps/web/src/app/(admin)/admin/conformite/_lib/get-compliance-alerts.ts` :

- `getComplianceAlerts()` : lit `compliance_items` (RLS
  `same_org`), applique `selectComplianceAlerts`, hydrate
  les labels d'entité (nom chauffeur, immatriculation véhicule,
  « Organisation ») via 2 lookups applicatifs (pas de FK polymorphe
  SQL, cf. ADR-013).
- `'server-only'` import → ne fuit pas côté client.
- Renvoie `ComplianceAlertEnriched[]` (alerte + `entity_label`).

### D-02 / D-03 — Affichage in-app

`<ComplianceAlertsPanel>` (client component) :

- Variantes : `'panel'` (cockpit, dense, en-dessous d'AlertsPanel) et
  `'card'` (dashboard, bordée, à côté de `ComplianceCard` RGPD).
- Compteur + liste compacte (entité, type, badge état dérivé).
- Si zéro alerte : message court « Aucune échéance à surveiller. »
- Lien « Gérer les échéances → /admin/conformite ».
- **Statut accessible** : icône + texte + jours (`<ComplianceBadge>`
  compact), pas couleur seule (WCAG 1.4.1).
- **Terracotta NON** (ce n'est pas un moment-clé d'action ; les
  alertes sont une vigilance, l'action concrète est dans
  `/admin/conformite`).

**Cockpit** :
- `cockpit/page.tsx` appelle `getComplianceAlerts()` en RSC.
- `CockpitContent` reçoit `complianceAlerts` en prop, l'aside passe
  en `flex-col gap-24` pour empiler `<AlertsPanel>` (courses) et
  `<ComplianceAlertsPanel>` (échéances) — distincts conceptuellement.
- Limite à 4 items visibles (cockpit dense).

**Dashboard** :
- `tableau-de-bord/page.tsx` appelle `getComplianceAlerts()` et place
  `<ComplianceAlertsPanel variant="card">` dans une grille
  `lg:grid-cols-2` aux côtés de `<ComplianceCard>` RGPD (les deux
  conformités côte à côte mais distinctes). Limite à 5 items.
