## 2. Surface 1 — Redirection par rôle

`apps/web/src/app/page.tsx` redirige aujourd'hui tout utilisateur connecté vers `/patients`. Phase 06.8 le remplace par une redirection **selon le rôle** :

| Rôle | Destination |
|---|---|
| `dirigeant` | `/tableau-de-bord` (nouveau — la page de cette phase) |
| `regulateur` | `/cockpit` (son outil opérationnel, inchangé) |
| `chauffeur` | `/conduite` (inchangé) |

- La route du dashboard est **`/tableau-de-bord`** — fichier `apps/web/src/app/(app)/tableau-de-bord/page.tsx`, dans le groupe `(app)` (shell authentifié : header + nav + UserMenu). Garde `requireDirigeantPage()` en tête : un régulateur ou un chauffeur qui force l'URL est redirigé.
- **Nav** : ajouter `{ href: '/tableau-de-bord', label: 'Tableau de bord' }` **en tête** de `DIRIGEANT_TABS` (`lib/nav-config.ts`). Le régulateur ne voit pas cet onglet (`REGULATEUR_TABS` inchangé — D-02).
- `app/page.tsx` reste un Server Component : il lit le rôle (`profiles.role`) et `redirect()`. Le rôle inconnu / non authentifié → `/login` (comportement actuel préservé).

## 4. Surface 3 — Anatomie d'une carte-KPI

Composant réutilisable `KpiCard`. Une carte = un conteneur `rounded-lg border bg-background p-16` (pattern des cartes du repo — il n'existe pas de primitive `Card`).

**Structure commune :**
- **Libellé** (`h3` / `text-sm font-medium text-muted-foreground`) — ce que mesure la carte.
- **Valeur principale** — gros chiffre (`text-2xl`/`text-3xl font-semibold tabular-nums`). C'est l'élément que le « test du flou » doit laisser lire.
- **État couleur** (optionnel) — pastille / texte sémantique vert / ambre / rouge selon un seuil. La couleur n'est jamais le **seul** porteur d'information (WCAG) : toujours doublée d'un texte (« seuil < 10 % », « 3 factures »).
- **Contexte** — courte ligne grise sous la valeur (`text-xs text-muted-foreground`), ex. « ce mois · tiers payant CGSS ».
- **Lien d'action** (bloc Action uniquement) — un `<Link>` explicite (« Facturer → ») en bas de carte ; toute la carte peut être cliquable, mais le lien reste un élément focusable distinct au clavier.

**Variantes :**
| Variante | Usage | Particularité |
|---|---|---|
| `simple` | KPI 1, 5, 6 | Libellé + valeur + contexte (+ lien si Action) |
| `ventilation` | KPI 3 (CA) | Valeur principale + petite liste libellé/montant (cash/CB/chèque/CGSS), montants alignés à droite `tabular-nums` |
| `multi` | KPI 4 (Volume) | 3 lignes Aujourd'hui / Semaine / Mois, valeurs alignées à droite |
| `alerte` | KPI 2 | Liste courte de lignes cliquables ; état vert si liste vide |

Toutes les variantes partagent l'en-tête (libellé) et la grille de la carte — l'exécution arbitre une prop `variant` ou des sous-composants ; chaque fichier ≤ 150 LOC.

## 5. Surface 4 — Les 6 KPIs

Pour chaque KPI : affichage, source (helper réutilisé — D-04), couleur/seuil, action.

### Bloc « À traiter » (Action)

**KPI 1 — Courses à facturer**
- Affiche : nombre de courses facturables CGSS du mois courant. Contexte « ce mois · tiers payant CGSS ».
- Source : `getCoursesFacturables(moisCourant).length` (`admin/facturation/_lib/queries-facturation.ts`).
- Couleur : neutre (informatif — un nombre élevé n'est pas une anomalie).
- Action : lien « Facturer → » vers `/admin/facturation`.

**KPI 2 — Alertes**
- Affiche : deux lignes — (a) « N factures incomplètes » (courses terminées tiers payant sans tarif) ; (b) « N no-shows (7 derniers jours) ».
- Source : (a) `getCountCoursesSansTarif(moisCourant)` ; (b) compte des `rides` avec `no_show_at` sur 7 jours glissants.
- Couleur : **rouge** si l'une des lignes > 0 ; **vert** + « Aucune alerte » si les deux sont à 0.
- Action : chaque ligne non nulle est cliquable → la liste filtrée concernée (factures incomplètes → `/admin/facturation` ; no-shows → `/courses` filtré). Si 0, pas de lien.

### Bloc « Activité » (Santé)

**KPI 3 — CA du mois + ventilation**
- Affiche : total encaissé du mois (gros chiffre, `€`) + ventilation Espèces / CB / Chèque / CGSS différé.
- Source : logique `CaisseTotals` (`caisse/_lib/queries-caisse.ts`) appliquée au **mois** courant. Le helper Caisse est journalier — une variante mensuelle réutilise **exactement** les mêmes critères (`status='terminee'` + `payment_status='encaisse'`, ventilation `by_method`), sans redéfinir « encaissé ».
- Couleur : neutre.

**KPI 4 — Volume de courses**
- Affiche : nombre de courses Aujourd'hui / cette Semaine / ce Mois.
- Source : compte sur `rides` par fenêtre temporelle (sur `scheduled_at` ou `ended_at` — l'exécution tranche pour la cohérence ; recommandation : courses planifiées sur la fenêtre).
- Couleur : neutre.

**KPI 5 — Taux de no-show / annulation du mois**
- Affiche : pourcentage = (`no_show` + `annulee_*`) ÷ total des courses du mois. Ligne de repère « seuil < 10 % » (benchmark NEMT).
- Source : comptes par `ride_status` + `no_show_at` sur le mois.
- Couleur : **vert** < 10 %, **ambre** 10-15 %, **rouge** > 15 % (seuils affinables au plan). Toujours doublé du texte du pourcentage et du seuil.

**KPI 6 — Activité chauffeurs**
- Affiche : nombre de chauffeurs avec ≥ 1 course aujourd'hui sur le total de chauffeurs actifs (`4 / 6`) + moyenne de courses par chauffeur.
- Source : `drivers` (actifs) + `rides` du jour groupées par `driver_id`.
- Couleur : neutre.

## 6. Surface 5 — Carte de statut de conformité (point sensible — D-10)

Statut **documentaire factuel**. Le RGPD (art. 5-2) impose de *démontrer* la conformité, pas de la revendiquer — la Phase 06.6 a délibérément évité tout satisfecit (disclaimer de non-certification). Cette carte reste dans le même esprit.

- **Affiche** : des compteurs factuels des tables `legal`, ex. :
  - `Registre : 6 traitements`
  - `DPA : 2 fiches`
  - `DPIA : brouillon` (ou `aucune`)
  - `Dernière mise à jour : 21/05/2026` (le `max(updated_at)` des tables legal, ou la date de la dernière entrée).
- **Lien** : « Gérer → » vers `/admin/legal`.
- **Section vide** : indiquée **factuellement et sans alarmisme** — « DPIA : aucune », « DPA : aucune fiche ». Pas de rouge, pas de croix, pas d'injonction.
- **Interdit** : feu vert global, mention « conforme RGPD », score ou pourcentage de conformité, coche de validation. La carte informe et oriente — elle ne juge pas.
- **Couleur** : neutre uniquement. Aucun état rouge/vert sur cette carte (un état couleur serait lu comme un verdict).

## 7. Surface 6 — États de la page

| État | Rendu |
|---|---|
| **Chargement** | Skeleton par carte (`ui/skeleton`) — la grille s'affiche, chaque carte montre des barres grises. Jamais de page blanche. Possible via `loading.tsx` ou `<Suspense>` par carte. |
| **Repos** | Cartes peuplées comme au wireframe. |
| **Vide / début d'activité** | Si une agrégation renvoie 0, message d'amorçage neutre **dans la carte** (« Aucune course ce mois », « Aucune alerte ») plutôt qu'un « 0 » sec trompeur. L'état vide de KPI 2 = vert « Aucune alerte ». |
| **Erreur** | Si une agrégation échoue, la carte concernée affiche un message sobre (« Indicateur indisponible ») — **sans casser le reste de la page**. Les autres cartes restent rendues. |

## 9. Checklist WCAG 2.2 AA (D-11 — obligatoire)

- **Contraste** : ≥ 4,5:1 texte courant, ≥ 3:1 grand texte / éléments graphiques. Couleurs sémantiques = tokens charte (jamais une palette par défaut de lib).
- **Couleur non seule porteuse** : tout état couleur est doublé d'un texte (pourcentage, libellé, « seuil < 10 % »).
- **Clavier** : chaque carte-Action et chaque lien atteignables et activables au clavier ; anneau de focus visible.
- **Cibles tactiles** : liens et zones cliquables ≥ 44×44 px.
- **Sémantique** : `h1` page, `h2` par bloc (« À traiter », « Activité »), `h3` libellé de carte ; HTML structuré pour les lecteurs d'écran. La grille reste lisible en ordre logique.
- **`prefers-reduced-motion`** : honoré ; aucune animation non essentielle (cohérent NFR-004, pas de framer-motion).
- **Test du flou** : à 10 % de résolution, le bloc « À traiter » et les valeurs principales restent identifiables (hiérarchie par position + taille).

## 10. Design tokens

Cohérent `/admin/tarifs`, `/admin/facturation`, UI-PATTERNS.md.

- **Spacing NFR-003** : `space-y-24` entre zones, `gap-16` grille, `p-16` carte, `space-y-4` interne carte. Échelle 4/8/12/16/24/32/48/64 uniquement.
- **Typographie** : titre page `text-2xl font-semibold tracking-tight` ; libellé de carte `text-sm font-medium` ; valeur KPI `text-2xl`/`text-3xl font-semibold` ; montants `font-mono tabular-nums` (alignement décimal).
- **Couleurs sémantiques** : vert succès / ambre attention / rouge alerte uniquement sur les KPIs à seuil (2, 5) ; cartes informatives et carte conformité = neutre (`text-foreground` / `text-muted-foreground`).
- **Icônes Lucide** (famille unique) : `FileText` (facturation), `AlertTriangle` (alertes), `Wallet` (CA), `CarFront` (volume), `UserCheck` (chauffeurs), `ShieldCheck` (conformité — neutre, pas un coche de validation).
- **Animations NFR-004** : aucune ; pas de framer-motion. Skeleton via `ui/skeleton`.

## 11. Anti-patterns (interdits)

- ❌ Rendre le dashboard accessible au régulateur (D-02 — dirigeant seul).
- ❌ Souscription temps réel / `postgres_changes` (D-03 — rendu au chargement).
- ❌ Réinventer une requête d'encaissement / de facturation au lieu de réutiliser les définitions de `queries-caisse` / `queries-facturation` (D-04).
- ❌ Carte de conformité avec feu vert, « conforme RGPD », score ou coche de validation (D-10).
- ❌ Bento grid / tuiles de tailles disparates (D-11 — grille simple).
- ❌ Graphes lourds, lib de graphes, palette par défaut de lib (D-09).
- ❌ Spécifier une carte ponctualité on-time ou utilisation flotte (D-07/D-08 — hors V1).
- ❌ Dupliquer le Cockpit régulateur (le dashboard = pilotage, pas régulation).
- ❌ La couleur comme seul porteur d'information (WCAG).
- ❌ Page blanche pendant le chargement (skeleton obligatoire).
- ❌ framer-motion (NFR-004).
