# Phase 06.12 — CONTEXT

> Solveur d'optimisation = heuristique TypeScript native dans `apps/web`.
> OR-Tools / Python / mock / hébergement séparé : SUPPRIMÉS.

## Pourquoi (faits)

- **Volume réel ≤ 500 courses absolu**, en pratique quelques dizaines par jour. Le contrat zod plafonne déjà à `rides.max(200)`.
- **OR-Tools est calibré pour 1000+ waypoints** — disproportionné ici. Sa lourdeur (binaires C++ ~75 MB) a bloqué l'hébergement Vercel : 5 PR de fix infructueuses (PR #196-#199), ADR-008 amendée, mock activé via `OPTIMIZER_USE_MOCK=true`.
- **Recherche OR** : pour fenêtres temporelles petites + horaires quasi-fixes (dialyse programmée = cas TAP), une heuristique greedy cluster-first/route-second est quasi-optimale.
- **Indicateurs affichés « estimés »** (DEC-081) — exactitude non contractuelle, l'heuristique suffit.
- **Bénéfice central** : supprime la SEULE barrière restante (hébergement Python). Plus de Python, plus de mock, plus de cold start, plus d'hébergeur tiers, zéro coût marginal. Tout dans `apps/web` (Vercel déjà payé). Le plan Vercel devient un non-sujet.

## Décisions fermées

### D-01 — Heuristique cluster-first/route-second dans `apps/web/src/lib/optimizer/`

1. **Clustering par compatibilité** : fenêtre temporelle (dérivée de `scheduled_at` + `urgency`, tolérances ±30 min programmée / ±60 urgente / ±15 immédiate — REPRENDRE de `solver.py:TOLERANCE_*`), type (`transport_mode` → `vehicle.type`), capacité (`places_assises`).
2. **Regroupement** : apparier les courses dont les fenêtres se chevauchent sur un véhicule compatible ; extension à n>2 si capacité OK. Les courses isolées → `rides_non_groupees_ids`.
3. **Ordonnancement (`order`)** : nearest-neighbor sur Haversine corrigée. Pas de 2-opt (volume trop petit pour gain tangible).
4. **`km_a_vide_estimes`** : somme Haversine des trajets sans passager entre dropoff et pickup suivant (logique de `_extract.py:_parcourir_route`).
5. **`motif`** : phrase courte cohérente DEC-081 (« estimé »). **`gain_km_a_vide`** par groupement = km économisés vs courses séparées.

### D-02 — Util Haversine TS partagé

Port direct des 44 lignes de `solver.py:haversine.py` dans `apps/web/src/lib/optimizer/haversine.ts`. Aucune dépendance nouvelle. `packages/pricing` contient déjà un Haversine privé — non extrait pour éviter une dépendance croisée pricing→optimizer ; les 2 implémentations cohabitent (identiques mathématiquement).

### D-03 — Brancher dans le Route Handler, retirer le détour HTTP

Dans `apps/web/src/app/api/optimizer/route.ts` point 7 : remplacer le bloc `useMock ? mockSolve(payload) : solve(payload, {HTTP})` par un appel direct `solveLocal(payload)`.

**CONSERVÉ** : auth Supabase, vérif rôle, dé-identification D-08, `ridesToSolveRequest`, `solveResponseToProposal`, `enrichProposal`, try/catch défensif.

**RETIRÉ** : imports `solve` / `OptimizerError`, `process.env.OPTIMIZER_USE_MOCK`, `VERCEL_URL` / `serviceUrl`, `timeoutMs: 30000`.

### D-05 — 6 scénarios pytest portés en Vitest

`test_solver.py` → `apps/web/src/lib/optimizer/solve-local.test.ts` (9 tests) + `haversine.test.ts` (4 tests, scénario 5).

Scénarios couverts :
1. Groupement simple — 2 courses fenêtres compatibles → 1 groupement.
2. Fenêtres incompatibles — 8 h vs 14 h → 0 groupement.
3. Mutualisation temporelle — Course B intercalée → 1 groupement avec order 4 stops.
4. Capacité respectée — 3 courses, véhicule 1 place → ≤ 2 par groupement, tracking complet.
5. Haversine + matrice (testé dans haversine.test.ts).
6. Dérivation des fenêtres horaires — tolérances par urgency.

C'est le filet d'équivalence fonctionnelle.

## Le contrat NE CHANGE PAS

`packages/optimizer-client/contract.ts` (zod) reste l'interface canonique.
`solveLocal()` produit exactement le même `SolveResponse` qu'OR-Tools :
`groupements{vehicle_id, ride_ids, order, motif, gain_km_a_vide}`,
`rides_non_groupees_ids`, `rides_exclues_ids`, `km_a_vide_estimes`.

`transform.ts` (`ridesToSolveRequest`, `solveResponseToProposal`) et `contract.ts` (zod schemas + types) sont CONSERVÉS sans modification. Le frontend `/cockpit/optimisation` ne voit aucun changement.
