**3 tables additionnelles** (RESEARCH §A2 + Pitfall 5/6) :

| Table | Visibilité | Justification |

| `cgu_acceptance` | RLS forcée, profile_id = auth.uid() | D-22 versioning CGU par profile (frontmatter MDX) |

**pg_cron jobs** :
- `breach-72h-watchdog` : `'0 * * * *'` → `check_breach_deadlines()` (insère `breach.deadline_warning` si > 66h sans notif CNIL)
- `legal-request-attempts-purge` : `'0 3 * * *'` → purge entries > 7 jours

**RPC `rgpd_anonymize_patient(uuid, uuid, text)`** :
- SECURITY DEFINER, `set search_path = public, extensions`
- Advisory lock `pg_advisory_xact_lock` (anti-double-call concurrent)
- UPDATE ONLY : `nir_encrypted=NULL`, `nir_search_hash` rehashé `extensions.digest(... || salt, 'sha256')`, identité directe → NULL, `archive=true`, `archive_reason='rgpd.art17.anonymisation'`
- DELETE uniquement sur `patient_constraint` + `patient_operational_note` (PII opérationnelles, pas de durée légale)
- **JAMAIS** DELETE patients ni rides (R5 RESEARCH, CSS L114-19, 5 ans)
- Audit log `patient.anonymized` avec `request_id`, `retention_basis`, `anonymized_at`

**RPC `nir_match_patient_for_legal_request(uuid, bytea, text, date)`** (B-1 fix iteration 2/3) :
- SECURITY DEFINER, scoped à l'org de la `patient_data_request`
- Match exact : NIR (bytea hash) + `lower(unaccent(nom))` + `date_naissance` + `archive=false`
- Retourne `uuid` ou `NULL`
- Requise par Plan 05 task 5.2 `verifyIdentityAction` (DPA-04)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing critical] ALTER patients DROP NOT NULL pré-requis art. 17**

- **Found during:** Task 2.2, exécution test rgpd_anonymize_patient.sql.
- **Issue:** Le RPC `rgpd_anonymize_patient` met `prenom`, `nom`, `date_naissance`,
  `adresse_ligne1`, `code_postal`, `ville` à NULL pour anonymiser. Or ces colonnes sont
  `NOT NULL` dans patients (Phase 1, par défaut métier saisie patient). Sans ALTER
  préalable, le UPDATE du RPC throw `null value in column "prenom" violates not-null
  constraint`. Le test 5 `prenom IS NULL` aurait échoué silencieusement.
- **Fix:** Ajout `alter table public.patients alter column ... drop not null` × 6 colonnes
  en tête de migration `20260508000005_rgpd_anonymize_rpc.sql`. Les CHECK constraints
  existantes (`length(trim(prenom)) between 1 and 80`, `code_postal ~ '^974[0-9]{2}$'`)
  restent inchangées : NULL passe ces checks par 3-Valued Logic SQL.
- **Files modified:** `supabase/migrations/20260508000005_rgpd_anonymize_rpc.sql`
- **Commit:** 063fa4e

**2. [Rule 1 — Bug] Test fixture nir_last4 violation check_constraint**

- **Found during:** Task 2.2, première exécution `rgpd_anonymize_patient.sql`.
- **Issue:** Le scaffold PLAN-01 insérait un patient avec `nir_last4 = '7823'`. Or
  Phase 1 patients.sql ligne 54 impose `check (nir_last4 is null or nir_last4 ~ '^[0-9]{2}\s[0-9]{2}$')`
  (format `XX YY` = 2 derniers digits + 2 digits clé, séparés par espace). L'insertion
  fixture lève `patients_nir_last4_check`, transaction abort, 0 assertion exécutée.
- **Fix:** `'7823'` → `'78 23'` (format conforme).
- **Files modified:** `supabase/tests/rgpd_anonymize_patient.sql`
- **Commit:** 063fa4e

**3. [Rule 3 — Blocking] pg_cron extension absente sandbox locale**

- **Found during:** Task 2.2, application `20260508000003_breach_72h_alert.sql`.
- **Issue:** Le plan demandait `create extension if not exists pg_cron with schema cron`.
  Or pg_cron n'est pas installé dans la Postgres locale Ubuntu 24.04 (Supabase Cloud
  l'a, pas la sandbox). Sans guard, la migration entière échoue ; impossible de
  compléter la Wave 1A en local.
- **Fix:** Wrap `create extension` dans un `DO` block conditionnel sur
  `pg_available_extensions where name = 'pg_cron'`. Idem pour les `select cron.schedule(...)`.
  En production Supabase Cloud, le block exécute normalement. En local, `raise notice`
  signale le skip (pas d'erreur).
- **Files modified:** `supabase/migrations/20260508000003_breach_72h_alert.sql`
- **Commit:** 4170f12
