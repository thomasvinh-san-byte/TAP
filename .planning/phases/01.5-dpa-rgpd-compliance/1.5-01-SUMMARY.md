## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Extension du `testDir` Playwright vers `tests/**`**

- **Found during:** Task 3, lors de la validation `playwright test --list`.
- **Issue:** Le plan exige des fichiers Playwright sous `apps/web/tests/admin/...`,
  `apps/web/tests/public/...`, `apps/web/tests/portail/...`. La config existante
  `testDir: './e2e'` ne les aurait pas découverts. Sans modification, le critère
  d'acceptance `pnpm exec playwright test --list | grep -c 'legal\|portail\|admin/registre' ≥ 6` aurait échoué.
- **Fix:** Étendu `testDir: '.'` + `testMatch: ['e2e/**/*.spec.ts', 'tests/**/*.spec.ts']`.
  Conserve `e2e/patient-flow.spec.ts` Phase 1.
- **Files modified:** `apps/web/playwright.config.ts`
- **Commit:** 84c4508
- **Documenté en commentaire** dans la config pour justifier la rétrocompat.

**2. [Rule 2 — Test robustesse] Pitfall 2 renforcé sur `patient_data_request_rls.sql`**

- **Found during:** Task 2, écriture du test pgTAP.
- **Issue:** Le plan demandait un assert `not (metadata->'new') ? 'request_token'`.
  Mais Pitfall 2 RESEARCH alerte aussi sur le risque que la valeur littérale du
  token apparaisse ailleurs dans `metadata` (ex: `old.metadata->'data'->>'token'`
  par jointure trigger non filtrée).
- **Fix:** Ajout d'une 8e assertion : `metadata::text not like '%JWT_FACTICE_TOKEN_SECRET_NE_DOIT_PAS_LEAK%'` qui scanne TOUT le payload metadata en clair.
- **Files modified:** `supabase/tests/patient_data_request_rls.sql`
- **Commit:** 21a8d40
