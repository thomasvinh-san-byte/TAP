## Détail technique

### Task 4.1 — Routing infrastructure

**`apps/web/src/middleware.ts`** : ajout de `isPublicLegal` (`pathname === '/legal' || pathname.startsWith('/legal/')`) et `isLegalApi` (`pathname.startsWith('/api/legal/cookie-consent')`) dans la condition de redirect login. Le `matcher` reste inchangé (les routes sont matchées par le middleware mais l'auth est skippée en code, donc supabase.auth.getUser() est toujours appelé pour les utilisateurs déjà connectés — comportement identique à `isAuthRoute`).

**`apps/web/src/app/(public)/layout.tsx`** (43 l.) : pas d'auth, header minimal avec lien `/login`, footer légal, bandeau cookies. Metadata template `'%s — TAP Régulation'`.

**`apps/web/src/app/(admin)/layout.tsx`** (59 l.) : double rideau SSR
1. `getUser()` → `redirect('/login')` si pas auth
2. `select('role').eq('id', user.id).single()` → `redirect('/')` si `role !== 'dirigeant'`
3. RLS Postgres D-18 = troisième rideau au niveau DB

Cast manuel `as { role: string } | null` (pattern existant `constraints.actions.ts` — limitation depth inference TS sur `.from().select().eq().single()`).

**`apps/web/src/components/footer.tsx`** (43 l.) : 5 liens `/legal/*` + bouton « Gérer mes cookies » qui appelle `resetCookieConsent` (dispatch d'un `CustomEvent('cookie-consent-reset')`).

**`apps/web/src/lib/cookie-consent.ts`** (58 l.) : helpers purs `readConsent` / `writeConsent` / `resetCookieConsent`, format `{ version: '1', choices, expires_at }`, TTL 6 mois (recommandation CNIL), invalide automatiquement si version diffère ou expirée.

### Task 4.2 — Banner + admin client + route consent

**`apps/web/src/components/cookie-banner.client.tsx`** (146 l.) :
- 3 boutons strictement identiques : `<Button variant="outline" className="flex-1 h-44">` (vérifié `grep -c 'flex-1 h-44'` = 3, mitigation T-1.5-14)
- Customize panel : checkbox techniques `checked disabled` (forcé), analytics `onChange`, marketing `disabled` + texte « non utilisé V1 »
- Listener `cookie-consent-reset` ré-affiche le banner sans reload, reset state customizing/choices
- Submit : write localStorage en premier (UX synchrone), POST API best-effort (catch silencieux)

**`apps/web/src/lib/supabase/admin.ts`** (23 l.) : factory `createAdminClient()` typée `Database`, fail-fast si env manquant, `persistSession: false`, **JSDoc explicite « JAMAIS exposer service_role au navigateur »**. Seul point d'import `@supabase/supabase-js` côté apps/web (W-3 DRY, ADR-001).

**`apps/web/src/app/api/legal/cookie-consent/route.ts`** (59 l.) :
- `export const runtime = 'nodejs'` (crypto Node + service_role)
- Validation zod : `technique: z.literal(true)`, `analytics: z.boolean()`, `marketing: z.boolean()`
- `user_agent_hash` = SHA-256 du header `user-agent` (jamais en clair, mitigation T-1.5-15)
- `session_token` = `crypto.randomBytes(16)` puis SHA-256 (token non lié à un compte)
- Insert via `createAdminClient` dans `cookie_consent_log` (table service_role-only Plan 02)
- Erreur reformulée en français, jamais de stack trace au client (CLAUDE.md § 1)
