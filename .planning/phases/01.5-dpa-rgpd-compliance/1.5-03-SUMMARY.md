# Phase 01.5 Plan 03 : Helpers RGPD purs (JWT + portabilité + anonymize + validators) Summary

Trois helpers TypeScript purs ≤ 50 lignes (`legal-token`, `patient-data-export`, `patient-anonymize`) + validators zod RGPD compliance (6 schemas, 7 enums alignés DB) ; 10 tests Vitest GREEN, briques prêtes pour Plans 04/05/06.

## Objective

Livrer les briques réutilisables pures consommées par les Server Actions admin (Plan 06), le portail patient (Plan 05) et les Edge Functions (Plan 04). Aucune dépendance UI, aucune mutation DB directe (toujours via vue `patients_safe` ou RPC SECURITY DEFINER).

## What was built

### `packages/shared/src/utils/legal-token.ts` (46 lignes)
- `signRequestToken({sub, org, type}) → Promise<string>` : JWT HS256, expiry 30 jours, claims minimaux verrouillés au type TS
- `verifyRequestToken(token) → Promise<RequestTokenClaims>` : algorithm strict HS256, clockTolerance 60s, throw si expiré/malformé/algo invalide
- `getSecret()` privée : valide `APP_LEGAL_TOKEN_SECRET` ≥ 32 bytes, fail-fast sinon

### `packages/shared/src/utils/patient-data-export.ts` (42 lignes)
- `generatePatientDataExport(supabase, patientId) → Promise<PatientDataExport>`
- Lit la vue `patients_safe` (jamais la table `patients` directe — T-1.5-11)
- Compose `format_version: '1.0'`, `exported_at` ISO 8601, patient + operational_notes + constraintes + audit_log filtrés par `entity_id`
- `nir` toujours `null` en V1 — décryptage via Edge Function `nir-decrypt` audité (Phase 1)

### `packages/shared/src/utils/patient-anonymize.ts` (33 lignes)
- `anonymizePatient(supabase, patientId, requestId) → Promise<void>`
- Délègue intégralement à la RPC SQL `rgpd_anonymize_patient` (transaction + advisory lock côté DB)
- Aucune mutation directe TS (T-1.5-12) — pas de `.update()`, pas de `.delete()`
- Valide `APP_ANONYMIZATION_SALT` ≥ 16 bytes, propage erreurs en français (`Anonymisation échouée : <message>`)

### `packages/shared/src/validators/legal.ts` (174 lignes)
- `dataProcessingRegisterSchema` (D-05) + `legalBasisEnum` (6 valeurs)
- `dpaRecordSchema` (D-06)
- `dpiaSchema` (D-07) + `dpiaStatusEnum` + `dpiaResidualRiskEnum` + refine cross-field
- `breachIncidentSchema` (D-08) + `breachSeverityEnum` + `breachNatureEnum`
- `dataRequestSchema` (D-09) + `dataRequestTypeEnum` (6 droits) + `dataRequestStatusEnum` (5 états)
- `dpoContactSchema` (D-15)
- 7 z.enum tous **alignés sur les contraintes CHECK** de la migration `20260508000001_legal_compliance.sql`
- 16 messages d'erreur français
- Types `z.infer` exportés pour usage côté Server Actions
