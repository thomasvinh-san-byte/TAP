## Contexte

La sandbox Claude Code ne peut pas tirer les images Docker du registry public
`public.ecr.aws/supabase/postgres:15.8.1.085` (HTTP 403 Forbidden depuis
CloudFront — voir log capturé dans le commit). Cette limitation est
**identique** à celles déjà documentées par les Plans 1.5-01, 1.5-02 et 1.5-03
de cette phase, ainsi que par les plans Phase 1 (cf. `1.5-01-SUMMARY.md` et
`1.5-02-SUMMARY.md`).

Le `pnpm db:reset` ne peut donc pas être exécuté ici. Mais :

1. Les **5 migrations RGPD** sont écrites, lintables, et présentes dans
   `supabase/migrations/` (Plan 1.5-02, vérifié) :
   - `20260508000001_legal_compliance.sql` (439 lignes)
   - `20260508000002_legal_additional_tables.sql` (96 lignes)
   - `20260508000003_breach_72h_alert.sql` (104 lignes)
   - `20260508000004_organizations_dpo_fields.sql` (28 lignes)
   - `20260508000005_rgpd_anonymize_rpc.sql` (165 lignes)

2. Les **types Supabase** sont régénérés manuellement dans
   `packages/database/src/types.gen.ts` (vérifié Plan 1.5-02 — pattern
   identique à Phase 1) avec toutes les nouvelles entités :
   ```
   data_processing_register   ✓
   dpa_record                 ✓
   dpia_record                ✓
   data_breach_incident       ✓
   patient_data_request       ✓
   cgu_acceptance             ✓
   cookie_consent_log         ✓
   legal_request_attempts     ✓
   rgpd_anonymize_patient     ✓
   dpo_contact_email          ✓
   ```

3. Les **7 fichiers pgTAP RGPD** sont présents dans `supabase/tests/` :
   ```
   data_processing_register_rls.sql
   dpa_record_rls.sql
   dpia_record_rls.sql
   data_breach_incident_rls.sql
   patient_data_request_rls.sql
   check_breach_deadlines.sql
   rgpd_anonymize_patient.sql
   ```

4. Le pipeline CI réel (GitHub Actions / Vercel preview) appliquera les
   migrations sur un Postgres managé Supabase et exécutera la suite
   pgTAP. Le **gate de phase** sera donc respecté côté CI/cloud.

## Commandes à exécuter en local (post-sandbox)

```bash
# 1. Démarrer Supabase local (Docker requis)
pnpm db:start
# ou : pnpm dlx supabase start

# 2. Reset complet — applique 4 migrations Phase 0/1 + 5 migrations Phase 1.5
pnpm db:reset

# 3. Régénérer les types (override manual file)
pnpm db:types

# 4. Vérifier les 5 migrations Phase 1.5 appliquées
supabase migration list 2>&1 | grep -E '20260508' | wc -l
# Attendu : 5

# 5. Vérifier les 2 cron jobs actifs
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c \
  "SELECT count(*) FROM cron.job
   WHERE jobname IN ('breach-72h-watchdog', 'legal-request-attempts-purge');"
# Attendu : 2

# 6. Suite pgTAP complète
pnpm db:test
# Attendu : 0 not ok, ~85+ assertions GREEN

# 7. Vérifier la RPC d'anonymisation
psql "postgresql://postgres:postgres@localhost:54322/postgres" -c \
  "SELECT pg_get_functiondef('public.rgpd_anonymize_patient'::regproc);"
# Attendu : code SQL non vide
```
