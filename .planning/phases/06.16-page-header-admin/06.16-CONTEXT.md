# Phase 06.16 — PageHeader admin commun — CONTEXT

## Goal

Extraire un composant `<PageHeader>` (titre + description + slot actions)
et l'appliquer aux **16 pages admin** qui réimplémentent chacune leur
`<header>` manuellement. Présentation pure, esprit Linear/Stripe (sobre,
dense). 0 logique métier touchée.

Décision dirigeant : **périmètre Strict**. Toolbar recherche/filtres
différée (du neuf qui touche la couche données et recoupe l'API tri/
pagination du `<DataTable>` laissée en V2).

## Pourquoi maintenant

Phase 06.15 vient d'uniformiser les 13 data tables sur `<DataTable>`. Les
16 pages admin restent l'unique foyer d'incohérence visuelle structurelle :
chacune réimplémente son `<header>` (toutes pattern `<h1>` + `<p>`, une
seule — `legal/registre` — a des actions dans le header). Aucun composant
`PageHeader` partagé n'existe.

Refondre ces en-têtes maintenant referme la promesse design system
(06.13 → 06.14 → 06.15 → 06.16) avant les phases produits suivantes.

## Décisions

### D-01 — Composant `<PageHeader>`

Créer `apps/web/src/components/page-header/`. API minimale :

```ts
interface PageHeaderProps {
  title: string;
  description?: ReactNode;
  actions?: ReactNode; // slot CTA/boutons à droite
}
```

Rendu **strictement aligné sur le pattern existant** (vérifié dans 16
pages) :

- Conteneur `flex items-center justify-between gap-16` quand `actions`
  fournies ; sinon simple bloc.
- Bloc gauche : `<h1 className="text-2xl font-semibold tracking-tight">`
  + `<p className="text-muted-foreground mt-4 text-sm">` si `description`.
- Bloc droit : `<div className="flex gap-12">{actions}</div>` si
  `actions`.
- Classes sémantiques tokens 06.14 uniquement (`text-muted-foreground`),
  aucun hex.

### D-02 — Appliquer aux 16 pages (D-01)

Remplacer chaque `<header>...</header>` manuel par
`<PageHeader title=... description=... actions=... />`. **Reprendre titre
et description à l'identique** — aucun texte réécrit. La structure des
pages au-dessus/au-dessous du header reste intacte.

### D-03 — Préserver les actions `legal/registre`

Seule page avec actions header (vérifié) :

```tsx
<PageHeader
  title="Registre des traitements"
  description="…"
  actions={
    <>
      <ExportPdfButton />
      <Button asChild>
        <Link href="#nouveau">…Nouvelle entrée</Link>
      </Button>
    </>
  }
/>
```

Les 15 autres pages : pas de prop `actions`.

### D-04 — Chrome inchangée

NE PAS toucher `(admin)/layout.tsx` ni `NavTabs` / `LegalNavMenu` /
`AdminTopBar`. Phase 06.16 ne concerne QUE le `<header>` de chaque
`page.tsx` admin.

## Garde-fous transverses

- Tokens 06.14 (classes sémantiques, jamais de hex). NFR-001 préservée.
- ≤ 300 LOC / fichier (le composant doit tenir < 50 LOC).
- 0 nouvelle dépendance npm.
- 0 migration BDD.
- Logique métier intacte (composant 100 % présentationnel).
- Jour + nuit à parité (le pattern actuel utilise déjà `text-muted-foreground`,
  donc rien à ajouter — `text-2xl` n'a pas de variante de couleur).
- RGAA : `<h1>` unique par page, `<p>` description sémantique standard.
