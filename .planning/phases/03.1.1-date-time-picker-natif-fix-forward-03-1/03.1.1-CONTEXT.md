## Phase Boundary

**Goal fonctionnel** : Remplacer `DateFreeformField` (chrono.fr based,
Phase 03.1) par 2 inputs natifs HTML date+time côte à côte. Modal tient
sur une page sans scroll sur mobile 375px et desktop.

**Goal UX** : Picker natif iOS/Android au lieu d'un parsing libre.
Compaction modal (gap-12, Textarea rows=2). Pas de calendrier custom.

**Effort estimé** : 30-45 min (2 fichiers modifiés, ~80 L net delta).

**Critère de fin** :
- Modal Nouvelle course ouvre 2 inputs natifs date + time côte à côte.
- Min today sur input date (validation client).
- Soumission crée la course avec `scheduled_at` ISO correct.
- Modal tient sur 1 page sans scroll mobile 375 et desktop 1280.

</domain>

## Implementation Decisions

### D-DTPICK-1 — Supprimer DateFreeformField

- Supprimer le composant `DateFreeformField` complet dans
  `ride-express-form-fields.client.tsx` (~50 L incl. chips 03.1).
- Supprimer toutes les références (export + chips inline + use).
- Plus de parsing libre — l'utilisateur saisit date+heure structurés.

### D-DTPICK-2 — Nouveau DateTimeFields inline

- Nouveau sous-composant `DateTimeFields` dans le MÊME fichier
  `ride-express-form-fields.client.tsx` (~30 L).
- Layout : `<div className="grid grid-cols-2 gap-12">` (NFR-003 spacing).
- Champ 1 : `<Input type="date" id="ride-date" min={todayISO} />` (DEC-005).
- Champ 2 : `<Input type="time" id="ride-time" step={300} />` (étapes 5 min).
- Props : `value: string | null` (ISO 8601 ou null), `onChange(iso)`,
  `error?: string | null`, `disabled?: boolean`.
- Helper local `combineToISO(date: string, time: string): string | null`
  qui retourne `new Date(\`${date}T${time}:00\`).toISOString()` si les
  2 sont remplis, sinon `null`.
- Affichage `error` sous les 2 champs (pattern existant Phase 03.1).

### D-DTPICK-3 — Réutiliser Input shadcn

- Le composant `Input` (`apps/web/src/components/ui/input.tsx`) spread
  props → `type` natif fonctionne directement.
- Pas de nouveau composant `/components/ui/`.

### D-DTPICK-4 — chrono-node : CONSERVER

- Grep effectué : `parseFreeformDate` utilisé dans 3 fichiers du modal :
  - `ride-express-form-fields.client.tsx` (DateFreeformField — à supprimer)
  - `use-ride-submit.client.ts` (fallback parsing — à simplifier)
  - `use-duplicate-check.client.ts` (fallback parsing — à simplifier)
- Tests + barrel + commentaire docstring restent.
- Résultat : **OUI utilisé ailleurs au moment du grep** → conserver
  chrono-node V1. Cleanup follow-up éligible (commit séparé) si dead
  code après ce PR.

### D-DTPICK-5 — Compaction modal

- `ride-express-modal.client.tsx` : `space-y-16` → `space-y-12` sur le
  `<form>` parent (D-DTPICK-5).
- `NotesField` (Textarea) : ajouter `rows={2}` (au lieu de default).

### D-DTPICK-6 — Validation côté client

- `min={todayISO}` sur input date (ISO `YYYY-MM-DD` du jour).
- Le serveur valide déjà via zod `scheduled_at` (DEC-005, refused-past).
- Pas de nouvelle règle server.

### D-DTPICK-7 — `lang="fr-FR"` sur les 2 inputs (best-effort)

- Posé directement sur `<input type="date">` et `<input type="time">`.
- Firefox + Safari : respectent partiellement → format FR (jj/mm/aaaa, 24h).
- Chrome desktop : ignore l'attribut, suit la locale OS du système.
- Mobile iOS Safari + Android Chrome : respectent la locale OS (FR par
  défaut côté Réunion = comportement souhaité).
- Coût : 2 props additionnels, aucun.

### D-DTPICK-8 — Preview FR via `Intl.DateTimeFormat`

- Ligne `text-xs text-muted-foreground` sous les 2 inputs.
- Visible UNIQUEMENT quand date ET time sont remplis (pas de preview
  bancal type `mardi 13 mai à --`).
- Format : `weekday: 'long', day: 'numeric', month: 'long', hour: '2-digit',
  minute: '2-digit'` → ex. `mardi 13 mai à 14:30`.
- Fallback garantissant la lecture FR indépendamment du navigateur Chrome
  desktop qui ignore le `lang`.
- `aria-live="polite"` pour annonce screen-reader lors d'un changement.

### D-DTPICK-9 — Responsive `min-w-0` (anti-débordement mobile 375)

- Les inputs natifs `date` et `time` ont une `min-width` implicite imposée
  par le navigateur (Chrome : ~150px chacun) qui casse le layout
  `grid-cols-2 gap-12` sur écran < 400px.
- Solution : `min-w-0` sur chaque `<Input>` du grid. Force le shrink.
- Aucune nouvelle classe utilitaire, aucune nouvelle dépendance.

~~Limitation Chrome desktop assumée V1.~~ → REMPLACÉ par D-DTPICK-19
(adoption shadcn DatePicker officiel). Le preview Intl reste documenté

### D-DTPICK-19 — Lift anti-pattern : adoption shadcn DatePicker officiel

Suite retour visuel utilisateur sur D-DTPICK-7..10 (lang fr-FR + preview
Intl) : la limitation Chrome desktop reste perçue comme cassée (picker
intrusif US, time AM/PM). Décision : lever l'anti-pattern initial et
installer le DatePicker shadcn/ui officiel.

3 nouvelles dépendances structurantes (réutilisées Phase 04 caisse +
Phase 05 récurrences + audit logs futur) :

- `@radix-ui/react-popover` (~5 KB) — primitif Radix officiel
- `react-day-picker` (~30 KB minified-brotli) — battle-tested OpenAI / Sonos / Adobe
- `date-fns` (~13 KB tree-shakeable + locale FR ~3 KB) — format unifié

Justification : shadcn UI officiel, pattern recommandé doc shadcn pour le
cas d'usage exact « date picker FR jj/mm/aaaa ». Non négociable face à
un masque text maison vu coût futur de maintenance + UX dégradée.

### D-DTPICK-20 — Composants shadcn scaffoldés manuellement

`npx shadcn@latest add popover calendar` non exécutable dans le sandbox.
Scaffoldé manuellement les 2 composants selon templates shadcn officiels :

- `apps/web/src/components/ui/popover.tsx` — wrapper Radix Popover Primitive
- `apps/web/src/components/ui/calendar.tsx` — wrapper react-day-picker
  - Personnalisation : `locale={fr}` par défaut (import depuis `date-fns/locale`)
  - Override possible via prop si futur caller a une autre locale

### D-DTPICK-21 — DateTimeFields réécrit (DatePicker + Select 96 créneaux)

Layout : `grid-cols-2 gap-12`. Champ 1 = DatePicker, champ 2 = Select temps.

**Champ 1 — DatePicker** :
- Trigger : `<Button variant="outline" className="w-full justify-start">`
  - Affiche `formatDateFr(date)` ou placeholder `jj/mm/aaaa`
  - Icône `CalendarIcon` Lucide à gauche
- PopoverContent : `<Calendar mode="single" disabled={(d) => d < startOfDay(new Date())} initialFocus />`
- Click sur un jour → `handleDayChange` + `setPopoverOpen(false)` (UX fluide)

**Champ 2 — Select 96 créneaux** :
- 96 options `00:00` à `23:45` (pas 15 min) générés par `Array.from({length:96})`
- 24H format par construction, indépendant locale browser
- `contentClassName="max-h-[260px] overflow-y-auto"` (96 items scrollables)
- Pattern Doctolib / Cal.com / Calendly pour le médical

Helper `combineToIso(date: Date, timeSlot: string): string | null` :
- Parse `hh:mm`, set hours+minutes sur Date, retourne `toISOString()`.

### D-DTPICK-23 — date-fns standardisée — `format-date-fr.ts`

Nouveau helper centralisé `packages/shared/src/utils/format-date-fr.ts` :

- `formatDateFr(date)` — `dd/MM/yyyy` (ex. `13/05/2026`)
- `formatTimeFr(date)` — `HH:mm` 24h (ex. `14:30`)
- `formatDateTimeFr(date)` — `EEEE d MMMM 'à' HH:mm` (ex. `mardi 13 mai à 14:30`)

Toute formatation date/heure FR du projet PASSE par ce module. Plus jamais
d'`Intl.DateTimeFormat` à la main éparpillé. Utilisé par DateTimeFields
maintenant, prévu pour audit logs (Phase 06), caisse (Phase 04), drawer
course timeline.

### D-DTPICK-24 — Aucune migration DB

`scheduled_at` reste `timestamptz` côté BDD, format-agnostic au stockage.
La saisie FR + format ISO ↔ BDD UTC sont gérés par date-fns côté client.

### D-DTPICK-25 — Bundle impact accepté

~50 KB tree-shakeable post-build (react-day-picker ~30 KB minified-brotli
+ date-fns ~13 KB + popover ~5 KB + locale FR ~3 KB). Investi : les 3 libs
serviront Phase 04 caisse (formatage), Phase 04 audit logs (timeline),
Phase 05 récurrences (calendrier mensuel). Pas de coût perdu sur une
feature isolée.
