<decisions>
## Implementation Decisions

### D-DTPICK-1 — Supprimer DateFreeformField

- Supprimer le composant `DateFreeformField` complet dans
  `ride-express-form-fields.client.tsx` (~50 L incl. chips 03.1).
- Supprimer toutes les références (export + chips inline + use).
- Plus de parsing libre — l'utilisateur saisit date+heure structurés.

### D-DTPICK-2 — Nouveau DateTimeFields inline

- Nouveau sous-composant `DateTimeFields` dans le MÊME fichier
  `ride-express-form-fields.client.tsx` (~30 L).
- Layout : `<div className="grid grid-cols-2 gap-12">` (NFR-003 spacing).
- Champ 1 : `<Input type="date" id="ride-date" min={todayISO} />` (DEC-005).
- Champ 2 : `<Input type="time" id="ride-time" step={300} />` (étapes 5 min).
- Props : `value: string | null` (ISO 8601 ou null), `onChange(iso)`,
  `error?: string | null`, `disabled?: boolean`.
- Helper local `combineToISO(date: string, time: string): string | null`
  qui retourne `new Date(\`${date}T${time}:00\`).toISOString()` si les
  2 sont remplis, sinon `null`.
- Affichage `error` sous les 2 champs (pattern existant Phase 03.1).

### D-DTPICK-3 — Réutiliser Input shadcn

- Le composant `Input` (`apps/web/src/components/ui/input.tsx`) spread
  props → `type` natif fonctionne directement.
- Pas de nouveau composant `/components/ui/`.

### D-DTPICK-4 — chrono-node : CONSERVER

- Grep effectué : `parseFreeformDate` utilisé dans 3 fichiers du modal :
  - `ride-express-form-fields.client.tsx` (DateFreeformField — à supprimer)
  - `use-ride-submit.client.ts` (fallback parsing — à simplifier)
  - `use-duplicate-check.client.ts` (fallback parsing — à simplifier)
- Tests + barrel + commentaire docstring restent.
- Résultat : **OUI utilisé ailleurs au moment du grep** → conserver
  chrono-node V1. Cleanup follow-up éligible (commit séparé) si dead
  code après ce PR.

### D-DTPICK-5 — Compaction modal

- `ride-express-modal.client.tsx` : `space-y-16` → `space-y-12` sur le
  `<form>` parent (D-DTPICK-5).
- `NotesField` (Textarea) : ajouter `rows={2}` (au lieu de default).

### D-DTPICK-6 — Validation côté client

- `min={todayISO}` sur input date (ISO `YYYY-MM-DD` du jour).
- Le serveur valide déjà via zod `scheduled_at` (DEC-005, refused-past).
- Pas de nouvelle règle server.

</decisions>
