## Color Tokens (reprise stricte UI-PATTERNS.md)

| Token | Usage Phase 04.5 |
|---|---|
| `--primary` | Bouton Submit modal assignation, focus ring |
| `--secondary` | Bouton Annuler, fond toggle pill inactif |
| `--muted` | Fond hover item dropdown, fond toolbar pills |
| `--muted-foreground` | Texte secondaire (méta POI, count, sections labels) |
| `--accent` | Surbrillance item sélectionné (Surface A et C) |
| `--destructive` | Badge "Incompatible" Surface C, texte erreur inline Surface B, warning lock |
| `--warning` | Badge "Filtre désactivé" Surface C toggle "Afficher tous" |
| `--success` | Badge "Compatible" Surface C, indicateur clé NIR valide Surface B |
| `--border` | Bordures inputs, séparateurs liste `divide-y` |

**Règle 60/30/10 (DEC-034) :**
- Dominant 60 % : fond background neutre + texte foreground
- Secondary 30 % : muted, secondary (filtres, méta)
- Accent 10 % : primary (CTA) + 1 signal sémantique par contexte (success OU warning OU destructive — jamais cumulés inutilement)

**Accent reservé pour :**
- `--primary` : CTA principal de la modal/sheet uniquement (1 par surface).
- `--success` / `--warning` / `--destructive` : badges status compatibilité Surface C, indicateur clé NIR Surface B, message erreur inline.
- **Jamais** sur les hovers, focus, ou éléments décoratifs.

# Surface A — AddressOrPOIPicker

### Pattern UI-PATTERNS.md référencé

- **Liste dense divide-y** (UI-PATTERNS.md « ListItem dense ») : `divide-y divide-border rounded-md border border-border`, item hauteur ~56-64 px, `hover:bg-muted`, `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-inset`.
- **Sections labellées discrètes** (nouveau micro-pattern dérivé) : header section en `text-xs text-muted-foreground uppercase tracking-wide` au-dessus de chaque groupe (POI / BAN), séparateur visuel par `<Separator />` shadcn ou simple `border-t border-border`.
- **Icônes différenciées Lucide** : `Hospital` pour POI catégorie santé, `Building` pour EHPAD/cabinet, `MapPin` pour BAN générique. Taille `h-16 w-16` (16 px), couleur `text-muted-foreground`.

### Spec composant

```ts
interface AddressOrPOIPickerProps {
  id: string;
  label: string;
  ariaLabel: string;
  value: string; // adresse texte affichée
  onChange: (payload: {
    label: string;
    code_postal?: string;
    ville?: string;
    notes_acces?: string; // pré-rempli si POI sélectionné
    source: 'poi' | 'ban' | 'libre';
  }) => void;
  onBlur?: () => void;
  tabIndex?: number;
  error?: string | null;
}
```

### États

| État | Trigger | Affichage |
|---|---|---|
| `idle` | Mount, value vide, pas de focus | Input avec placeholder, icône MapPin gauche |
| `typing` | < 3 caractères tapés | Helper text « Tapez au moins 3 caractères pour rechercher. » |
| `loading` | ≥ 3 caractères, requête en cours | Skeleton 2 lignes dans le dropdown ou spinner discret à droite de l'input |
| `results` | Réponse non vide | Dropdown 2 sections (POI puis BAN) ; sections masquées si vides |
| `no-results` | Réponse vide | Empty state texte « Aucun lieu ne correspond à « {query} ». La saisie libre est conservée. » |
| `error` (BAN down) | `results.isError` | Toast sonner discret (existant) ; POI seul affiché si disponible |
| `picked` | Sélection ou édition initiale avec value non vide | Mode pill : `MapPin` + texte + bouton « Changer » (pattern existant conservé) |

### Comportement clavier

- `↓` : focus suivant dans la liste (POI d'abord, puis BAN dans l'ordre)
- `↑` : focus précédent
- `Enter` : sélectionner l'item focus
- `Esc` : ferme le dropdown sans sélectionner (focus revient à l'input)
- `Tab` : sort du composant si dropdown fermé, sinon ferme et focus suivant champ
- Mode pill : `Enter` ou `Space` sur le bouton Changer rouvre le mode recherche

### A11y

- `<input role="combobox" aria-expanded={openDropdown} aria-controls="address-listbox" aria-activedescendant="...">`
- `<ul role="listbox" id="address-listbox" aria-label="Suggestions de lieux">`
- `<li role="option" aria-selected={focused}>` pour chaque item
- Séparateurs section : `<li role="presentation" aria-hidden="true">` ou `<li role="group" aria-label="Lieux fréquents">`
- Empty state annoncé : `aria-live="polite"`
- Erreur inline : `role="alert"` (déjà présent dans le composant existant)

### Variants

**Variant `empty-query`** (< 3 caractères) :
- Pas de dropdown affiché
- Helper text sous l'input (caption muted)

**Variant `poi-only`** (BAN error, POI matches available) :
- Section « Lieux fréquents » seule
- Pas de section « Adresses »
- Pas d'erreur affichée (toast suffit)

**Variant `ban-only`** (POI vide, BAN OK) :
- Section « Adresses » seule
- Pas de section « Lieux fréquents »
- Comportement identique au composant existant

**Variant `no-results`** :
- Empty state texte sous l'input (caption muted), pas de dropdown
- « La saisie libre est conservée. » — la `value` actuelle reste utilisable au submit

**Variant `picked` (mode pill, conservé du composant existant)** :
- `MapPin` 16 px + texte truncate + bouton ghost « Changer » à droite
- Si source = `poi`, ajouter un sous-titre 12 px muted avec le nom POI canonique (ex : « CHU Félix Guyon »)
- Click Changer → revient en `idle` avec value vidée

### Préremplissage notes_acces (D-10)

Lorsqu'un POI est sélectionné (source = `poi`) :
- `adresse`, `code_postal`, `ville` sont remplis depuis la POI
- `notes_acces` est pré-rempli depuis `pois_metier.notes_acces` (ex : « Entrée Urgences, parking visiteurs à droite »)
- Le champ `notes_acces` (en aval, hors Surface A) doit refléter la valeur avec un sous-label « Pré-rempli depuis le lieu, modifiable » (caption muted)

Lorsqu'une adresse BAN est sélectionnée :
- `notes_acces` reste vide ou conservé tel quel (pas d'écrasement)

### Spec champs

#### Date de naissance

- Composant : `react-datepicker` (déjà importé Phase 03.2, `DateTimeFields`).
- Format affichage : `JJ/MM/AAAA` strict, locale `fr`.
- Validation Zod : refine `date_naissance` âge ∈ [0, 130] ans.
- Erreur inline : « Date invalide. Format attendu : JJ/MM/AAAA, âge entre 0 et 130 ans. »
- A11y : `<input aria-label="Date de naissance">`, icône `Calendar` Lucide à droite (cliquable pour ouvrir le picker).
- Densité : hauteur input 40 px (h-10 shadcn standard), placeholder visible « JJ/MM/AAAA ».

#### NIR

- Input contrôlé avec masque progressif d'affichage : `X 00 00 00 000 000 00` (espaces visuels uniquement, non envoyés au serveur).
- Largeur fixe : grid col 1, max 240 px (chiffres tabulaires).
- Indicateur clé contrôle (A-01) à droite de l'input :
  - 14 chiffres saisis : icône `CircleDashed` (muted)
  - 15 chiffres + clé valide : icône `CheckCircle2` (`text-success`)
  - 15 chiffres + clé invalide : icône `XCircle` (`text-destructive`)
- Helper text neutre sous le champ (caption muted) tant que pas de submit : « 15 chiffres : sexe + année + mois + département + commune + ordre + clé. »
- Erreur inline au submit ou blur si invalide.
- Conformément RGPD données santé : `autocomplete="off"`, pas de copy/paste track, pas de log côté client.

#### Téléphone

- Masque saisie : `0X XX XX XX XX` (espaces visuels).
- Préfixes autorisés (A-03) : `0262`, `0263`, `0692`, `0693`. Refus métropole.
- Erreur inline si autre préfixe : « Le numéro doit commencer par 0262, 0263, 0692 ou 0693 (10 chiffres). »
- Largeur input : max 200 px, chiffres tabulaires.
- Helper text optionnel sous le champ (caption muted) : « Fixe Réunion ou mobile Réunion. »

#### Code postal + Ville (auto-complétion liée)

- **Layout** : 2 colonnes `grid grid-cols-[120px_1fr] gap-12`.
- **Code postal** :
  - Préfixe `974` rendu en `<span>` muted dans un addon gauche (style `Input` shadcn avec prefix slot, ou wrapper personnalisé `flex items-center` autour de l'input).
  - 2 chiffres saisissables seulement, masque `[0-9]{2}` au keydown.
  - Erreur inline : « Code postal Réunion : 974 + 2 chiffres (ex : 97400). »
- **Ville** :
  - `Select` shadcn avec `<SelectContent>` filtré par recherche fuzzy (liste fermée 24 communes 974, A-02).
  - Auto-complétion : à la saisie du code postal complet (5 chiffres), si match exact dans la table `code_postal → ville`, le champ ville est rempli automatiquement.
  - Si CP correspond à plusieurs villes (ex : 97400 = Saint-Denis), prendre la commune dominante (logique côté validators avec mapping interne).
  - Disabled si CP non valide. Erreur inline si vide au submit : « Sélectionnez une commune dans la liste (24 communes Réunion). »

#### Nom + Prénom

- Regex `^[A-Za-zÀ-ÿ\s'-]+$` (lettres + accents + espace + apostrophe + tiret).
- `text-transform: capitalize` CSS sur l'input affiché (pas de transformation côté state — affichage uniquement, valeur brute conservée).
- Erreur inline si chiffres ou symboles : « Lettres uniquement (accents, tirets et apostrophes autorisés). »
- 2 colonnes : `grid grid-cols-2 gap-12`.

### Pattern erreur inline

Pattern unique pour tous les champs (DEC-030 + UI-PATTERNS.md) :

```tsx
<div className="space-y-8">
  <Label htmlFor="nir">NIR</Label>
  <Input
    id="nir"
    aria-invalid={!!error}
    aria-describedby={error ? 'nir-error' : 'nir-help'}
    className={cn(error && 'border-destructive focus-visible:ring-destructive')}
  />
  {!error && (
    <p id="nir-help" className="text-xs text-muted-foreground">
      15 chiffres : sexe + année + mois + département + commune + ordre + clé.
    </p>
  )}
  {error && (
    <p id="nir-error" className="text-xs text-destructive" role="alert">
      {error}
    </p>
  )}
</div>
```

- Helper text et erreur **ne s'affichent jamais simultanément** (helper laissé pour aide, erreur prend la place).
- `aria-describedby` toujours pointé sur l'élément actif (helper ou erreur).
- Couleur `--destructive` réservée à l'erreur + indicateur NIR invalide. Pas de bordure rouge sur les champs non-touchés (only after blur ou submit).

### Logique compatibilité (rappel — implémentation côté hook `useMemo`)

| Véhicule (`vehicle.type`) | Chauffeur compatible si |
|---|---|
| `tpmr` | `'tpmr' ∈ driver.type_permis[]` |
| `vsl` | `'vsl' ∈ driver.type_permis[]` OR `'taxi' ∈ driver.type_permis[]` |
| `taxi` | `'taxi' ∈ driver.type_permis[]` |
| `ambulance` | `'ambulance' ∈ driver.type_permis[]` |

Tri par défaut :
1. Si toggle `Compatibles` actif : compatibles uniquement, ordre alphabétique nom
2. Si toggle `Afficher tous` actif : compatibles d'abord (ordre alphabétique), puis incompatibles (ordre alphabétique, séparés par `border-t` ou ligne sentinelle visuelle discrète)

```tsx
  onClick={() => setSelectedDriverId(driver.id)}

    'flex w-full items-center gap-12 px-16 py-12 text-left hover:bg-muted focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-inset',
    selectedDriverId === driver.id && 'bg-accent/30'
  )}
>
  <InitialsAvatar name={driver.nom_affichage} size={32} role="chauffeur" />
  <div className="flex-1 min-w-0">
    <div className="text-sm font-semibold truncate">{driver.nom_affichage}</div>
    <div className="text-xs text-muted-foreground truncate">
      Permis {driver.type_permis.join(' + ')}
    </div>
  </div>
  {compatible ? (
    <Badge className="bg-success/10 text-success border-success/20">
      Compatible
    </Badge>
  ) : (
    <Badge variant="destructive" className="bg-destructive/10 text-destructive border-destructive/20">
      Incompatible
    </Badge>
  )}
</button>
```

Maximum **1 badge par ligne** (Surface C n'utilise qu'un badge compatibilité — conforme à la règle « ≤ 3 badges/ligne »).

### Warning incompatible sélectionné

Si `selectedDriverId` correspond à un chauffeur `Incompatible` :
- Bloc warning entre la liste et le footer du Dialog
- `bg-warning/10 border border-warning/20 rounded-md px-16 py-12`
- Icône `AlertTriangle` Lucide 16 px + texte 14 px destructive
- Texte : « Ce chauffeur n'a pas le permis requis pour ce véhicule. Confirmez en connaissance de cause. »
- Bouton submit reste actif (l'urgence prime — DEC-029 esprit pragmatique), mais nécessite confirmation visuelle par le warning affiché.

### A11y

- Toggle pills : `role="tablist"`, chaque pill `role="tab" aria-selected={active}`.
- Liste chauffeurs : `role="listbox" aria-label="Chauffeurs disponibles"`, items `role="option" aria-selected={selectedDriverId === driver.id}`.
- Warning : `role="alert" aria-live="polite"` (n'apparaît qu'à la sélection d'un incompatible).
- Badge sémantique : pas d'`aria-hidden` — texte « Compatible »/« Incompatible » est annoncé par les lecteurs d'écran (utile pour la régulatrice si non-visuel).

### Empty states

**Aucun chauffeur compatible** (toggle `Compatibles` actif) :
```
┌────────────────────────────────────────────────┐
│       🚗 (icône CarTaxiFront muted)            │
│   Aucun chauffeur compatible                   │
│   avec un véhicule {type}.                     │
│   Activez « Afficher tous » pour basculer en   │
│   mode urgence.                                │
│           [Afficher tous]                      │
└────────────────────────────────────────────────┘
```

**Aucun chauffeur du tout** (rare, organisation vide) :
- Empty state existant conservé (« Aucun chauffeur actif. »).

## Risques UI identifiés

### Accessibilité

- **Surface A** : combobox/listbox ARIA pattern requiert tests lecteur d'écran (VoiceOver macOS minimum). Risque : sections labels « Lieux fréquents » / « Adresses » non annoncées si mal taggées. → Mitigation : utiliser `<li role="presentation">` pour les headers ou `aria-label` sur `<ul role="group">`.
- **Surface B** : indicateur clé NIR visuel (icône CheckCircle2 / XCircle) doit être doublé par `aria-live="polite"` sur le helper text pour les non-voyants. Sinon discrimination visuelle.
- **Surface C** : badge Incompatible doit avoir contraste ≥ 4.5:1 sur le fond (test WCAG AA). `bg-destructive/10` + `text-destructive` à vérifier — possiblement passer à `text-destructive` sans fond pour respecter contraste sur muted hover.
- **Toutes surfaces** : ordre Tab logique vertical (input → dropdown items → submit). Tester sur tous les variants.

### Mobile (test 375 px iPhone SE)

- **Surface A** : dropdown 320 px max → OK sur 375 px viewport. Vérifier truncation des labels longs (CHU + nom complet) avec `truncate` CSS.
- **Surface B** : grid 2 colonnes (Nom/Prénom, CP/Ville) → passer en 1 colonne `< sm:` via `grid-cols-1 sm:grid-cols-2`. Sheet largeur `w-full` sur mobile (au lieu de `w-[480px]`).
- **Surface C** : Dialog modal pleine largeur mobile, toolbar pills `flex-wrap` pour permettre retour à la ligne si search + toggle ne tiennent pas. Badges « Compatible/Incompatible » doivent rester visibles (pas truncated).

### Performance

- **Surface A** : debounce autocomplétion 200 ms (D-08) — éviter requête BAN à chaque keystroke. POI métier doit être query-cached côté React Query (staleTime 5 min — liste fermée ~30 items).
- **Surface B** : validation Zod refine asynchrone interdite (clé NIR doit être synchrone côté client — algo simple sans I/O). Pas de roundtrip serveur pour la validation de format.
- **Surface C** : filteredDrivers calculé via `useMemo` (existant ligne 90-92 du `assign-modal`), à étendre avec filtre compatibilité. Re-render uniquement à la sélection de véhicule ou changement query.

### Risques visuels (DEC-034 conformité)

- Ne pas introduire de cards aérées (anti-pattern UI-PATTERNS.md).
- Ne pas dépasser 3 badges/ligne (Surface C = 1 seul badge, OK).
- Tous les spacings doivent être sur la scale 8 px — vérifier `px-12 py-12` (12 px = OK car scale = 4/8/12/16/24…).
- Couleur `bg-warning/10` réservée aux warnings — vérifier que le toggle « Afficher tous » ne déclenche pas warning sur lui-même (warning seulement si incompatible sélectionné).
