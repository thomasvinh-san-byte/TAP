## Implementation Decisions

### TRONC 1 — Workflow chauffeur

- **D-01 (T1.1)** : `apps/web/src/app/(driver)/conduite/page.tsx` ajoute logging défensif identique au pattern PR #63 (`page.tsx` admin chauffeurs). Capture `ridesRes.error` + `driversRes.error` (si applicable) avec `message / code / details / hint / user_id / role / organization_id` côté Vercel Runtime logs. Hypothèses prioritaires à investiguer via le logging : H1 RLS `rides_select` filtre rôle chauffeur sans `driver_id` match, H2 `resolveMyDriverId` retourne null malgré profile_id correct, H3 query Supabase échoue silencieusement, masquée par `data ?? []`. Le logging défensif reste après fix (defense in depth).
- **D-02 (T1.2)** : Le seed `seed.demo.sql` **utilise déjà** `date_trunc('day', now() - interval '3 days')` etc. — dates relatives. La cause root de la "dette seed" observée en UAT est différente : `ON CONFLICT DO NOTHING` empêche le ré-application sur rides existantes. **Fix retenu** : ajouter une logique `INSERT … ON CONFLICT (id) DO UPDATE SET scheduled_at = EXCLUDED.scheduled_at, started_at = EXCLUDED.started_at, ended_at = EXCLUDED.ended_at, created_at = EXCLUDED.created_at` (uniquement pour rides démo `id LIKE '44444444-%'`). Idempotent + glissant.
- **D-03 (T1.3)** : Nouveau test E2E `apps/web/tests/e2e/driver-workflow-complete.spec.ts` couvrant : login chauffeur → assert ≥ 1 course visible → démarrer → assert toast + bouton clôturer → clôturer avec tarif + paiement → assert statut terminée → cleanup BDD si non-idempotent. V1 acceptable non-idempotent avec skip si seed consommé (dette test future).

### TRONC 2 — Qualité saisie patient

  - ✅ `codePostalReunionSchema` : `^974[0-9]{2}$`

  - ❌ **À AJOUTER** : regex nom/prénom `^[A-Za-zÀ-ÿ\s'-]+$` (actuellement min/max seulement)

Tous les messages français user-facing respectent DEC-030 (cadratins → `:`, anglicismes → français).
- **D-07 (T2.3 — tests E2E)** : Nouveau `apps/web/tests/e2e/patient-form-validation.spec.ts` couvrant les 7 scénarios brief (nom avec chiffres, NIR 20 chars, date 30/02, téléphone US, code postal métropole, adresse hors BAN, submit valide).
