# Phase 06.31 — CONTEXT

> Composant `<SegmentedControl>` sobre (toggle Actifs / Archivés) —
> factorise une duplication et corrige un design daté.

## Pourquoi

Le toggle « Actifs / Archivés » avait un design daté et était **dupliqué
3 fois** à l'identique :

- `(app)/patients/_components/patients-list.client.tsx`
- `(admin)/admin/chauffeurs/_components/drivers-list.client.tsx`
- `(app)/courses/_components/assign-modal.client.tsx`

Défauts précis :

- Conteneur `p-2` (2px) → pastille active colle aux bords, effet « bouton
  qui déborde ».
- Contraste actif via `bg-background shadow-sm` sur `bg-muted/40` →
  différenciation portée par une OMBRE → aspect « bouton enfoncé » daté.
- Actif sans poids typo (juste `text-foreground` vs `text-muted-foreground`).
- Pas de transition de la pastille, pas de focus ring soigné.

## Décisions fermées

### D-01 — Créer `<SegmentedControl>` + `<SegmentedNav>`

`components/ui/segmented-control.tsx` (**126 LOC**, sous la limite 150) :

- **`<SegmentedControl>`** : segments = `<button>`, usage state local
  (patients-list, assign-modal).
- **`<SegmentedNav>`** : segments = `<Link>`, usage navigation URL
  (chauffeurs `?vue=`).

Choix de séparation : 2 composants plutôt qu'un seul avec prop optionnelle
`href`. Avantage : types stricts (le button ne peut pas oublier
`onValueChange`, le link ne peut pas oublier `href`), API plus claire,
même 126 LOC restent < 150.

API générique `<T extends string>` :

```ts
interface SegmentOption<T extends string> {
  value: T;
  label: ReactNode;
}

interface SegmentedControlProps<T extends string> {
  options: SegmentOption<T>[];
  value: T;
  onValueChange: (v: T) => void;
  ariaLabel: string;
  className?: string;
}

interface SegmentedNavOption<T extends string> extends SegmentOption<T> {
  href: LinkProps['href'];
}
```

Style cible (extraits) :

```ts
const containerCls = 'inline-flex items-center gap-4 rounded-lg bg-muted p-4';
const segmentActiveCls = 'bg-background text-foreground font-medium shadow-sm';
const segmentInactiveCls = 'text-muted-foreground hover:bg-background/50 hover:text-foreground';
const segmentBaseCls = 'rounded-md px-12 py-6 text-sm transition-all duration-150 ' +
  'focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-muted';
```

Améliorations vs l'ancien :
- `p-4` (padding réel) vs `p-2` (collait aux bords).
- `gap-4` interne entre segments.
- `rounded-lg` sur le conteneur (vs `rounded-md`).
- **`font-medium`** sur l'actif (poids typo = différenciation forte).
- `transition-all duration-150` (vs `transition-colors` sans durée explicite).
- Focus ring avec `ring-offset-muted` (lisible sur fond `bg-muted`).
- Hover sur inactif inclut `bg-background/50` (feedback plus net).
- Bordure du conteneur supprimée (Linear/iOS pattern : la pastille suffit).

Accessibilité préservée : `role="tablist"`, `role="tab"`, `aria-selected`,
`aria-label` obligatoire.

### D-02 — Remplacer les 3 duplications

| Fichier | Avant | Après |
|---|---|---|
| `patients-list.client.tsx` | 30 lignes inline (div + 2 buttons) | `<SegmentedControl value={scope} onValueChange={setScope} ... />` (9 lignes) |
| `drivers-list.client.tsx` | `ViewToggle` interne 36 lignes (div + 2 Links) | `<SegmentedNav<Vue> value={currentVue} ... />` (8 lignes) |
| `assign-modal.client.tsx` | 35 lignes inline (boolean toggle) | `<SegmentedControl<'compat'\|'all'>` avec mapping boolean ↔ string (9 lignes) |

**Comportement strictement INCHANGÉ** : mêmes valeurs, même filtrage, même
navigation, mêmes aria-labels.

Conséquences techniques :
- `patients-list` : `import { cn }` retiré (plus utilisé).
- `drivers-list` : `import Link from 'next/link'` retiré (remplacé par
  `<SegmentedNav>`).
