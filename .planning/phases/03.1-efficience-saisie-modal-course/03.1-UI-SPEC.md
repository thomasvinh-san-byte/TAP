## Element 1 — Chips date rapides

**Position** : inline dans `DateFreeformField`, **après** l'`<Input>` et
**avant** le `<p>` d'erreur. Pas de wrapper card. Conteneur :
`<div className="flex flex-wrap gap-8 mt-8">`.

**Valeurs des chips** (D-A3-2, ordre figé) :

| Index | Label affiché | Comportement |
|-------|---------------|--------------|
| 0 | `demain 8h` | `onChange('demain 8h')` puis `onParsed(iso)` |
| 1 | `demain 14h` | `onChange('demain 14h')` puis `onParsed(iso)` |
| 2 | `lundi 9h` | `onChange('lundi 9h')` puis `onParsed(iso)` |
| 3 | `dans 30 minutes` | `onChange('dans 30 minutes')` puis `onParsed(iso)` |

**Classes Tailwind locked (D-A3-3) — à coller verbatim** :

```
px-12 py-8 rounded-full text-xs border border-input bg-background hover:bg-muted text-muted-foreground transition-colors
```

**Markup attendu (référence non-normative)** :

```tsx
<button
  type="button"
  onClick={() => handleChipClick('demain 8h')}
  className="px-12 py-8 rounded-full text-xs border border-input bg-background hover:bg-muted text-muted-foreground transition-colors"
>
  demain 8h
</button>
```

**États interactifs** :
- repos : `bg-background border-input text-muted-foreground`
- survol : `hover:bg-muted`
- focus clavier : anneau hérité du focus-visible global (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2` si absent du style natif `<button>` ; à hériter via global CSS ou ajouté localement)
- désactivé : non applicable — les chips ne s'affichent pas en mode édition
- transition : 150 ms via `transition-colors`

**Conditions d'affichage (D-A3-5)** :
- Affichés UNIQUEMENT si `!props.disabled && !props.rideId`
- En mode édition (`rideId` présent) : chips totalement masquées (pas `aria-hidden`, simplement non-rendues)
- En mode disabled : idem non-rendues

**Accessibilité** :
- Chaque chip est un `<button type="button">` (non-submit, ne déclenche pas la soumission)
- Label textuel = aria-label implicite (texte enfant)
- Pas d'icône, pas de tooltip — la valeur textuelle se suffit
- Cohérence clavier : Tab atteint chaque chip dans l'ordre, Enter / Space déclenche

**Anti-patterns explicites pour cet élément** :
- ❌ Ne pas utiliser le composant shadcn `<Button variant="outline" size="sm">` (trop épais visuellement à `h-9` / `h-10` — D-A3-3 référence chips Linear)
- ❌ Pas d'icône Lucide dans la chip (lourdeur inutile)
- ❌ Pas d'animation au click (le parsing déclenche déjà la rétroaction via l'input qui se remplit)
- ❌ Pas de toast de confirmation (smart defaults silencieux — cohérent avec A2)

## Element 2 — Banner doublon amber

**Position** : à l'intérieur du `<form>` de `RideExpressModal`, **avant**
`<DialogFooter>` (le planner tranche entre « juste avant `<DialogFooter>` »
ou « en tête du DialogContent ». Recommandation : juste avant
`<DialogFooter>` pour proximité maximale du bouton submit qui a déclenché
la détection).

**Conditions d'affichage (D-B3-3)** :
- Visible UNIQUEMENT si `duplicates.length > 0 && !duplicateConfirmed`
- Caché par défaut (premier rendu modal)
- Reset à la fermeture / création réussie (D-B3-5)

**Classes Tailwind locked (D-B3-4) — à coller verbatim sur le conteneur racine** :

```
rounded-md border border-amber-500/50 bg-amber-50 dark:bg-amber-950/30 px-16 py-12 space-y-8
```

**Structure du contenu** :

```
[Titre]      Course en doublon détectée
[Liste]      • {heure}  —  {statut humanisé FR}
             • {heure}  —  {statut humanisé FR}     (max 3 lignes)
[Boutons]    [ Annuler ]  [ Créer quand même ]
```

**Détail des sous-éléments** :

| Sous-élément | Markup / classes | Copy FR |
|--------------|------------------|---------|
| Titre | `<p className="text-sm font-medium text-amber-900 dark:text-amber-100">` | `Course en doublon détectée` |
| Liste doublons (1-3 items) | `<ul className="text-sm text-amber-900/80 dark:text-amber-100/80 space-y-4">` avec `<li>` non puces (ou `list-disc list-inside`) | `{HH:mm} — {statut}` par item (cf. table statuts ci-dessous) |
| Conteneur boutons | `<div className="flex gap-8 justify-end pt-4">` | — |
| Bouton « Annuler » | `<Button type="button" variant="outline" size="sm">` | `Annuler` |
| Bouton « Créer quand même » | `<Button type="button" variant="destructive" size="sm">` | `Créer quand même` |

**Mapping statuts humanisés FR** (cohérent reformulation existante) :

| Code DB | Affiché dans banner |
|---------|---------------------|
| `validee` | `validée` |
| `assignee` | `assignée à un chauffeur` |
| `en_cours` | `en cours` |
| `terminee` | `terminée` |

**Comportements boutons** :

- **« Annuler »** : ferme le banner (`setDuplicates([])` ou équivalent), ne ferme PAS la modal, le formulaire reste rempli. La régulatrice peut corriger l'heure ou changer de patient.
- **« Créer quand même »** : `setDuplicateConfirmed(true)` puis re-déclenche `handleSubmit()`. Bypass la vérification doublon une fois.

**Reset** (D-B3-5) : après création réussie, avant `props.onClose()`,
réinitialiser `duplicateConfirmed = false` et `duplicates = []`. Si la
régulatrice rouvre la modal, l'état est propre.

**Accessibilité** :
- `role="alert"` sur le conteneur racine (annonce immédiate au lecteur d'écran)
- `aria-live="polite"` (cohérent avec patterns d'erreur existants ex. `login-form.client.tsx`)
- Focus management : à l'apparition, focus déplacé sur le bouton « Annuler » (action sûre par défaut, principe de moindre surprise)
- Contraste : `amber-900` sur `amber-50` ≈ 8.5:1 (WCAG AAA texte normal) ; en sombre `amber-100` sur `amber-950/30` ≈ 11:1

**Anti-patterns explicites pour cet élément** :
- ❌ Pas de variant rouge `destructive` sur le conteneur (le banner est un warning, pas une erreur — D-B3 explicite « non-destructif »)
- ❌ Pas d'icône Lucide `AlertTriangle` proéminente (référence Linear : warnings sobres sans pictogramme). Si le planner juge l'accessibilité dégradée, une icône `Info` 16px `text-amber-700` à gauche du titre est tolérée mais non requise.
- ❌ Pas de modale de confirmation au clic « Créer quand même » (le bouton lui-même est la confirmation — cohérence avec pattern Linear)
- ❌ Pas d'animation d'apparition (transition `fade-in` shadcn par défaut suffit ; pas de `slide`, pas de `bounce`)
- ❌ Pas de fermeture auto-temporisée (le banner reste jusqu'à action explicite)

## Conformité piliers CLAUDE.md

**Pilier 1 — UX qui donne envie d'être utilisée** :
- Chips Linear-like, plates et discrètes → pas de surcharge visuelle pour 8h/jour d'usage
- Banner non-bloquant → respect de l'expertise de la régulatrice (elle décide)
- Aucun toast ni pop-up superflu → respect Pilier 1 « pas d'infantilisation »
- Saisie express course ≤ 30 s préservée : les chips accélèrent, le banner n'apparaît que sur conflit réel

**Pilier 2 — Design system rigoureux** :
- Spacing strict 8/12/16 uniquement (NFR-003 respecté)
- Une seule famille d'icônes (Lucide, optionnel pour cette phase)
- Mode clair + sombre traités à parité (`dark:bg-amber-950/30`)
- 5 états interactifs sur les chips (repos / hover / focus / actif transitoire / non-rendu si édition)
- Transitions 150 ms via `transition-colors`

**Pilier 3 — Sécurité** : non-applicable à la couche UI de cette phase
(la sécurité est portée par la Server Action `checkDuplicateRideAction`
avec `getAuthContext` + whitelist rôle + RLS Postgres — voir CONTEXT.md
D-B3-1).
