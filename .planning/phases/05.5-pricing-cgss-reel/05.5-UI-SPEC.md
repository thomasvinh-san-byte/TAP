## 2. Sources industry 2026 consolidées (4 sources)

### Source 1 — Breakdown facture / line items (Stripe Billing)

Pattern dominant 2026 : décomposition en **lignes label↔montant** alignées, séparateur visuel avant le total, total en gras + taille supérieure. Les montants en police monospace tabulaire (alignement décimal). Chaque ligne optionnelle n'apparaît que si non-nulle (pas de « 0,00 € » bruyant).
→ **Application TAP** : `PricingBreakdown` `<dl>` lignes conditionnelles, total `border-t` + `font-semibold text-base`, `font-mono tabular-nums`.

### Source 2 — Rate cards admin versionnées (SaaS billing admin 2026)

Les UIs admin de grilles tarifaires affichent la **grille active en évidence** (carte mise en avant) + un **historique tabulaire** des versions (date d'effet, statut actif/archivé). L'édition crée une **nouvelle version** plutôt que de muter l'existante (audit + rollback). Date d'effet = champ central.
→ **Application TAP** : `/admin/tarifs` carte « Grille active » + table historique + édition = INSERT nouvelle ligne `tariff_grids` (DEC-057).

### Source 3 — Simulateur de prix live

Pattern « calculatrice » : formulaire d'entrées à gauche/haut, résultat recalculé en temps réel à droite/bas (`useMemo`, pas de bouton « Calculer »). Le résultat réutilise la **même fonction de calcul** que la production (cohérence garantie).
→ **Application TAP** : simulateur `/admin/tarifs` réutilise `computeCgssShortTrip` (fonction pure DEC-057) avec la grille active, recalcul `useMemo` sur changement d'entrée.

### Source 4 — Transparence billing / réduction des litiges

Les billing UIs 2026 réduisent les litiges en explicitant chaque composante (« pourquoi ce montant »). Un disclaimer sobre sur le statut du tarif (estimatif vs définitif) évite l'ambiguïté contractuelle.
→ **Application TAP** : disclaimer DEC-061 « tarif estimatif, non contractuel jusqu'à facturation CGSS (Phase 06) », ton sobre, pas d'alarme.

Sources : saasframe.io (SaaS billing UI 2026), pipelineroad.com (Stripe per-transaction breakdown), patterns Stripe Billing / rate card admin.

**Lignes — règles d'affichage** :

| Ligne | Condition d'affichage | Format |
|-------|----------------------|--------|
| Forfait prise en charge | toujours | `13,00 €` — mention « 4 km inclus » |
| Distance / km facturés | `distance_km !== null` | `X,X km · Y,Y km facturés × Z,ZZ €/km` → montant |
| Supplément DROM | `supplement_drom_eur > 0` | `+ 3,00 €` |
| Supplément TPMR | `supplement_tpmr_eur > 0` | `+ 30,00 €` |
| Majoration | `majoration_eur > 0` | label dynamique : « Majoration nuit / week-end / jour férié (+50 %) » |
| Total | toujours | `font-mono tabular-nums` + `Modifier` si `editable` |
| Disclaimer | toujours | icône `Info` Lucide, `text-xs text-muted-foreground` |

**Label majoration dynamique** : un champ `majoration_motif: 'nuit' | 'weekend' | 'ferie' | null` dans `PricingResult` (DEC-061) détermine le libellé. Une seule majoration possible (non-cumulables DEC-059).

**Distance non calculable** (`distance_km === null`, adresse saisie libre sans coords) : afficher « Distance non disponible — forfait seul » au lieu de la ligne km ; le total = forfait + suppléments + majo. Disclaimer renforcé.

**États** : repos / `editable` (bouton Modifier → Surface B) / read-only (chauffeur end-ride-modal).

La grille précédente devient « archivée » (la grille active = celle avec la `date_effet` la plus récente ≤ aujourd'hui).

**Zone « Historique »** : table dense (lignes 40px, cohérent cockpit Phase 05) — date d'effet, forfait, km 974, DROM, TPMR, majo, statut (Active / Archivée). Tri par date d'effet desc.

**Intégration nav** : ajouter `/admin/tarifs` au menu admin (cohérent `/admin/sms-templates`, `/admin/chauffeurs`).

## 9. Anti-patterns (interdits)

- ❌ Garder le badge « DEMO » (DEC-061 le retire).
- ❌ Hardcoder le tarif km 974 / DROM dans un composant (DEC-057 — toujours depuis `tariff_grids`).
- ❌ UI transport partagé / abattements / retour à vide / Grande Ville (DEC-058 — Phase 06).
- ❌ Présenter le tarif comme définitif/contractuel (disclaimer estimatif obligatoire DEC-061).
- ❌ framer-motion (NFR-004).
- ❌ Bouton « Calculer » dans le simulateur (recalcul live `useMemo`).
- ❌ Muter une grille existante à l'édition (DEC-057 = INSERT nouvelle version).
- ❌ Noms propres patient/chauffeur dans le simulateur (NFR-001 — entrées numériques).
- ❌ Afficher les lignes nulles (« 0,00 € » bruyant) — lignes conditionnelles.
