## 2. Spacing Scale

Échelle stricte 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px (NFR-003, CLAUDE.md § 1 pilier 2). Aucune
valeur intermédiaire autorisée (`px-3`, `px-5`, `px-6`, `gap-10`, `space-y-20`, etc.).

| Token Tailwind | Valeur | Usage canonique Phase 04 |
|----------------|--------|--------------------------|
| `4` | 4 px | Bordure interne icône, espace inline minuscule, offset focus ring |
| `8` | 8 px | Gap chip/badge, padding inner Button compact, gap dot-status / label ConnectionStatus |
| `12` | 12 px | Padding lateral Input (`px-12`), gap icône-label, padding Cell CaisseTable |
| `16` | 16 px | Espacement standard champ-à-champ formulaire (`space-y-16`), padding contenu Modal/Dialog |
| `24` | 24 px | Padding section Card, espacement bloc-à-bloc dans AuthShell, marge titre de page |
| `32` | 32 px | Padding panneau AuthShell (split identité ↔ form), gap entre sections caisse |
| `48` | 48 px | Padding extérieur landing AuthShell desktop, hauteur logo TAP zone identité |
| `64` | 64 px | Marge top page régulateur (header sticky 56 px + 8 px), zone respiratoire en bas de page |

**Hauteurs de champs (piège documenté CONVENTIONS.md)** : utiliser l'échelle Tailwind par défaut en
rem pour les `h-*` de Input/Select/Button taille default. **Ne PAS écrire `h-40` (=160 px).**

| Élément | Classe | Hauteur |
|---------|--------|---------|
| Input / Select / Button desktop régulateur | `h-10` | 40 px |
| Button principal desktop saillant (CTA login, submit caisse) | `h-12` | 48 px |
| Button principal chauffeur (≥ 56 px CHAUF-01) | `h-14` | 56 px |
| Header sticky régulateur | `h-14` | 56 px |

| Cellule sous-total `<tfoot>` (CaisseTable) | `h-14` | 56 px (légèrement plus aérée que les lignes) |
| Bouton "back" PWA Driver Shell (gros, accessible au pouce) | `h-14` minimum, largeur `w-14` | 56 × 56 px |

**Largeurs canoniques drawers/sheets** (CONVENTIONS.md) : 400 px patient, 480 px course/driver.
La phase 04 ne crée pas de nouveau drawer ; OverrideTarifModal est un `Dialog` (modal centré),
pas un Sheet.

**Largeurs canoniques modal** :

| Modal | Largeur max |
|-------|-------------|

**Exceptions** : aucune. Si un écran nécessite un cran intermédiaire, c'est le mauvais cran de

| Body | 16 px | 400 | 1.5 | `text-base leading-[1.5]` | Texte courant formulaire, Input value, Modal body |

- Liens hypertexte

### Mode nuit — points de parité critiques

| Surface | Vérification parité jour/nuit |
|---------|-------------------------------|
| `/login` AuthShell | Capture publiable jour + nuit (compte pour 1 livrable dans le 5/5 Visible Progress) |
| ConnectionStatus dot | Les 3 couleurs (success, warning, destructive) doivent rester lisibles en mode nuit sans clignotement |

| DemoCredentials cards | Cards distinguées du fond en mode nuit via bordure `border` et hover `--accent` |

### Contraste WCAG AA

Toute combinaison texte/fond doit satisfaire ratio ≥ 4.5:1 (CLAUDE.md § 5). Les tokens
`muted-foreground` (jour `215 16% 47%` / nuit `215 20% 65%`) ont été choisis pour rester
conformes — ne pas les remplacer par des variantes "plus discrètes".

## 6. États interactifs et animations

Référence NFR-005 + CLAUDE.md § 1 pilier 2.

### 5 états obligatoires par élément interactif

| État | Style |
|------|-------|
| Repos | Selon variant (button primary = `bg-primary text-primary-foreground`) |
| Survol (hover desktop) | Variation luminosité subtile (Tailwind `hover:bg-primary/90`), transition 150 ms |
| Pressé (active) | `active:scale-[0.98]` + opacité légèrement réduite (`active:bg-primary/85`) |
| Actif (élément sélectionné/courant) | Bordure colorée `--primary` ou background `--primary/10` selon contexte |
| Désactivé | `disabled:opacity-50 disabled:cursor-not-allowed disabled:pointer-events-none` |

### Focus clavier

Anneau coloré avec offset (CLAUDE.md § 1) : `focus-visible:outline-none focus-visible:ring-2
focus-visible:ring-ring focus-visible:ring-offset-2`. **Jamais `focus:outline-none` sans
focus-visible alternative.** Visible sur tous les éléments interactifs, en mode jour ET nuit.

### Transitions

- Durée default : 150 ms (déjà configurée `tailwind.config.ts` `transitionDuration.DEFAULT`)
- Easing default : `cubic-bezier(0, 0, 0.2, 1)` (ease-out — déjà configuré)
- Respect strict `prefers-reduced-motion: reduce` (déjà cablé dans `globals.css`)

### Animations spécifiques Phase 04

| Animation | Surface | Spec |
|-----------|---------|------|
| Slide-in route PWA Driver | Transition `/conduite` ↔ `/conduite/[rideId]` | `slide-in-from-right` 250 ms ease-out. **Pas de spring physics, pas de scale**. Utiliser `tailwindcss-animate` (déjà installé). Verrou D-context "PAS d'animations élaborées". |
| Spin subtil dot ConnectionStatus état "synching" | Header `/conduite` | Rotation 2 s linéaire, opacité dot pulsant 80%↔100%. Subtil, jamais clignotant. |
| Fade-in CaisseTable expand row | Lignes courses sous le chauffeur expandé | `animate-fade-in` 200 ms (déjà défini `globals.css` ligne 92). |
| Optimistic UI submit boutons PWA Driver | Démarrer / Clôturer course | État pending immédiat (label `Démarrage…` / `Clôture…`) + `aria-busy="true"`. Pas de spinner overlay. |
| Toggle jour/nuit AuthShell | Bouton icône Sun/Moon | Transition couleur 150 ms sur tous les tokens via `:root` ↔ `[data-theme='dark']`. Pas de flash blanc (SSR-cookie première lecture obligatoire). |
