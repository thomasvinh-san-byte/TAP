# Phase 06.17 — Conformité des champs de saisie — CONTEXT

## Goal

Mettre **tous les champs de saisie du projet** (132 champs sur 50
fichiers) aux **normes UX/a11y consensuelles** (NN/G, Deque, Shopify
Polaris, USWDS, W3C ARIA APG) via des composants communs. Pas de
débat d'architecture — application directe.

Trois sujets liés, traités ensemble :

- **A** — Aide générale : helper text persistant, exemples, numériques
  sans spinner avec défaut cohérent.
- **B** — Autocomplétion Marque + Modèle (combobox éditable dépendante).
- **C** — Normalisation au submit (Title Case sur saisies libres, trim
  partout).

**Pas de pilote** : périmètre = tous les champs du projet. Découpé en
plusieurs PR séquentielles si nécessaire pour rester gérable (cf.
section « Multi-PR plan » ci-dessous).

## Multi-PR plan (séquencement)

L'ampleur du périmètre (132 champs, 50 fichiers) justifie un découpage
en 3 PR séquentielles SOUS la même phase 06.17. Le périmètre n'est

- **PR1 (cette PR — #230)** — Composants communs + véhicule/chauffeur :
  `<Field>` commun, `<Combobox>` éditable accessible, catalogue

- **PR3** — Reste : `dpia`, `dpa-prefill`, `accept-invite`, `dpo`,

## Principe directeur (normes, pas du goût)

- Helper text **PERSISTANT** pour les formats/contraintes (jamais en
  placeholder seul, qui disparaît à la frappe).
- Placeholder = exemple de valeur, jamais reformulation du label.
- Numériques bornés : pas de spinner (`inputMode=numeric`). **Valeur
  par défaut cohérente avec les bornes** : un champ `min=1` ne démarre
  jamais vide.
- Autocomplétion de données = pattern combobox accessible W3C APG.
- Champs à format bornés en `maxLength`.

## Principe directeur (normes, pas du goût)

NN/G + Deque + Shopify + USWDS, consensus : **si l'utilisateur a besoin
de l'indice pour réussir le champ, l'indice va dans un helper text
persistant** (sous le champ ou le label), **JAMAIS dans un placeholder**
(qui disparaît à la frappe). Le placeholder = exemple de valeur court,
jamais une reformulation du label. W3C APG : autocomplétion =
pattern combobox accessible (role + ARIA + clavier).

  (NN/G : à proscrire pour les bornes serrées). Modèle = texte 100 %

## Contrainte stack (DEC-003)

Pas de nouvelle dépendance npm. Les normes imposent le **comportement**
combobox (ARIA), pas un outil précis. La combobox est construite sur
les primitives déjà présentes (`<Input>` + `<Label>` + `<button>` +
positionnement CSS) avec navigation clavier maison conforme W3C APG.

## Décisions

### D-01 — Composant `<Field>` commun

`apps/web/src/components/form/field.tsx`. Étend la signature actuelle
(`id`, `label`, `error` + `InputHTMLAttributes`) avec :

- `hint?: ReactNode` — helper text persistant sous l'input, lié à
  l'input via `aria-describedby`. Survit à la saisie.
- `placeholder?` — exemple de valeur uniquement (transmis tel quel
  comme attribut HTML standard).

Consomme tokens 06.14 (`text-muted-foreground`, `text-destructive`).
Remplace les `Field` locaux dupliqués de `vehicle-form` et `driver-form`.

### D-02 — Helper text persistant pour les champs à format

Le `hint` s'affiche sous le champ, **survit à la saisie**, lié par
`aria-describedby` (lecteur d'écran). Si une `error` est présente,
elle remplace visuellement le `hint` (mais reste liée à `aria-describedby`).
Jamais d'instruction critique en placeholder seul.

### D-03 — Champs numériques bornés SANS spinner

Places assises (1-9), places TPMR (0-3), valeurs entières connues :
passer de `type="number"` à `type="text"` + `inputMode="numeric"` +
`pattern="[0-9]*"` (clavier numérique mobile, **pas de spinner ni de
molette accidentelle** sur desktop — bug récurrent NN/G). Hint = bornes
en clair (« 1 à 9 », « 0 à 3 »). Validation `min/max` côté Server
Action **inchangée** (zod schema).

### D-04 — Composant `<Combobox>` éditable accessible

`apps/web/src/components/form/combobox.client.tsx`. Combobox W3C APG :

- `role="combobox"` sur l'input.
- `aria-expanded`, `aria-controls`, `aria-autocomplete="list"`,
  `aria-activedescendant`.
- Listbox `role="listbox"`, options `role="option"` + `aria-selected`.
- Navigation clavier : ↑/↓ pour parcourir, Enter pour commit, Échap
  pour fermer, Tab pour fermer + sortir.
- Filtrage flou côté client (normalisation NFD pour les accents,
  includes insensitive).
- Saisie libre autorisée (`allowFreeText: true` par défaut) — la valeur
  hors liste est acceptée et soumise telle quelle.

Props : `id`, `label`, `options: readonly string[]`, `value`,
`onChange`, `hint?`, `error?`, `placeholder?`, `allowFreeText?`,
`disabled?`, `autoFocus?`, `name?`. Soumis comme `<input>` HTML
standard (le champ caché n'est pas requis — le DOM expose `value`).

### D-05 — Catalogue Marque → Modèle

`apps/web/src/lib/vehicles/catalog.ts`. `Record<marque, modèle[]>` pour
les marques fréquentes du parc (Renault, Peugeot, Citroën, Dacia,
Mercedes-Benz, VW, Ford, Toyota, Opel, Fiat, Nissan, Hyundai, Kia).
Marques prioritaires FR/974 listées d'abord. Modèles dans chaque marque
triés alphabétiquement.

**Non exhaustif** par construction : la saisie reste libre côté UI
(`allowFreeText`). Le catalogue accélère la saisie pour les cas
fréquents sans bloquer les modèles rares. Maintenu à la main, versionné,
zéro API tierce.

Exporte aussi `normalizeBrandOrModel(value)` (D-07).

### D-06 — Marque et Modèle = comboboxes dépendantes

Formulaire véhicule :

- **Marque** : `<Combobox>` sur `VEHICLE_BRANDS` (les clés du
  catalogue), saisie libre permise.
- **Modèle** : `<Combobox>` dont les `options` sont calculées par
  `modelsForBrand(marque)` :
  - Marque connue → liste de modèles connus (`hint` : « Modèles connus
    pour {marque}. »).
  - Marque libre/inconnue → tableau vide, combobox en saisie libre
    pure (`hint` : « Saisie libre. »).
- Pas de reset automatique du modèle au changement de marque (évite
  d'effacer une saisie en cours).

### D-07 — Normalisation au submit

Server Action véhicule : `trim` + Title Case sur marque/modèle saisis
librement (`normalizeBrandOrModel` exporté par `catalog.ts`). Limite
les doublons d'orthographe (« renault » → « Renault ») sans bloquer
la saisie. Acronymes en MAJUSCULES préservés (BMW, VW). Les valeurs
choisies dans la combobox passent inchangées car déjà canoniques.

### D-08 — Inscription ROADMAP

Entrée `[ ] Phase 06.17` insérée juste après 06.16 (premier acte de
cadrage, convention 06.13 → 06.16).
