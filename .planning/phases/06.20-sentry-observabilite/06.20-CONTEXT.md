## Pourquoi

Sentry est dans la stack figée (DEC-003) mais jamais installé. Aujourd'hui : 33 `console.error` partent dans le vide en prod, 18 fichiers avec try/catch sans remontée, 1 seul `error.tsx`. RETEX : « les agents IA écrivent du code qui marche mais sans observabilité » — exactement le risque d'un projet bâti avec Claude Code. Sans Sentry, debug en prod à l'aveugle. **Sentry déjà dans la stack figée → pas de nouvel ADR requis** (activation d'un choix acté).

## CONTRAINTE CRITIQUE — données de santé (RGPD)

TAP manipule des données de santé indirectes (patients, transport sanitaire). Sentry ne doit JAMAIS capturer de PII patient.

- **`sendDefaultPii: false`** sur les 3 runtimes.
- **Session Replay** : DÉSACTIVÉ par défaut (laissé en commentaire dans `instrumentation-client.ts` avec `maskAllText: true` + `blockAllMedia: true` si réactivé un jour).
- **Scrubbing `beforeSend`** : helper partagé `lib/sentry/scrub.ts` qui retire toute clé sensible (NIR, nom, prénom, adresses, téléphone, email, date_naissance, tokens) des events/breadcrumbs avant envoi. Headers `Cookie` / `Authorization` / `X-Supabase-Auth` masqués. URLs : query string retirée. User : seul l'`id` auth conservé. 6 tests Vitest.
