## Goal

Le chauffeur installe la PWA sur son téléphone, travaille hors-ligne 1 h, mutations syncées au retour réseau.

Manifest et icônes maskable, splash iOS DPR + manifest auto-généré Android, `ConnectionStatus` header 4 cas, transitions fade-in via `template.tsx` (DEC-020 — slide bidirectionnel iOS-style reporté Phase UI dédiée, bug Next.js #42658).

## Périmètre — dans

- Manifest static + 4 icônes (192/512 `any` + `maskable`)
- Splash iOS `apple-touch-startup-image` 3 DPR minimum (iPhone SE / 13-14 / 15 Pro Max)
- `apple-touch-icon` 180×180 (iOS home screen)
- Serwist scaffold (`withSerwistInit`, scope `/conduite*`, `reloadOnOnline: false`, `disable: NODE_ENV === 'development'`)
- Dexie 4.x schema : table `mutations_queue` + miroir local courses du jour
- Sync engine : queue, retry exponentiel 2s + jitter ±500ms, max 30s, **3 essais max**, dead letter queue avec toast Sonner destructive
- **Route Handlers explicites** `/api/driver/rides/[id]/start|end` (DEC-045 LOCKED, Alt A préféré sur Server Actions via fetch headers `Next-Action`)
- `ConnectionStatus` header 4 cas : `online idle`, `synching`, `offline + queue`, `offline idle` — avec `useLiveQuery` Dexie sur `pendingCount`
- `navigator.storage.persist()` au mount PWA + tracking `lastUsedAt` + warning UI banner si > 7 j inactivité (DEC-022)
- Listener `window.addEventListener('online', flushQueue)` pour replay (Background Sync API non supporté iOS 17+/18 confirmé recherche)
- Transitions fade-in via `template.tsx` (DEC-020 — slide bidirectionnel iOS-style reporté Phase UI dédiée)

## Périmètre — hors (reporté)

- Hors-ligne > 1 h (Phase 06)
- Push notifications Web Push API VAPID (Phase 06)
- Géolocalisation temps réel (Phase 06)

## Stratégie cross-platform iOS + Android (Option A validée 2026-05-18)

Décision dirigeant discuss : **Option A — Cross-platform équilibré**.

PWA = standard Web installable. Fonctionne nativement sur iOS Safari (depuis iOS 11.3, 2018) et tous les browsers Android principaux (Chrome, Edge, Samsung Internet, Firefox).

**Pourquoi Option A** :

- **iOS Safari = pire-cas technique** : si la PWA fonctionne sur iOS (le plus restrictif), elle fonctionne automatiquement sur Android. Tester d'abord iOS = trouver les bugs limites absents sur Android.
- **Effort marginal iOS** : ~2-3h sur 9.5h total pour splash 3 DPR + `apple-touch-icon` + tests Safari. Négligeable en temps réel (vélocité projetée 2-3h sur 9.5h estimé).
- **Conformité PWA standard 2026** : icônes maskable + splash iOS = checklist pro reconnue par design partners.
- **Différenciateur produit** : « installable sur le téléphone du chauffeur » est un pitch fort vs SaaS web classique. Ne pas renoncer à cette valeur (Option C web-only abandonnée).

**Contexte 974 réaliste** :

- Probable que la majorité des chauffeurs design partner soient sur Android (Samsung A-series, Xiaomi Redmi dominant marché 974 mid-range). Une minorité iPhone (souvent dirigeants).
- Mais le test iOS reste prioritaire (pire-cas), Android suit naturellement.

### iOS (Safari)
- `apple-touch-icon` 180×180 (home screen icon)
- `apple-touch-startup-image` 3 DPR minimum :
  - iPhone SE 750×1334 (4.7", iOS 17+)
  - iPhone 13/14 1170×2532 (6.1", iOS 17+)
  - iPhone 15 Pro Max 1290×2796 (6.7", iOS 17+)
- `apple-mobile-web-app-capable` + `apple-mobile-web-app-status-bar-style`
- IndexedDB purge mitigation : `navigator.storage.persist()` au mount (WebKit heuristique home screen install accorde généralement)
- Background Sync API : NON supporté → fallback `window.addEventListener('online', flushQueue)`
- Web Push : reporté Phase 06 (VAPID iOS 16.4+)

### Android (Chrome / Edge / Samsung Internet)
- `manifest.json` standard avec :
  - 4 icônes (192×192 et 512×512 en `any` + `maskable`)
  - `theme_color` cohérent identité TAP
  - `background_color`
  - `display: 'standalone'`
  - `orientation: 'portrait'` (chauffeur 1 main)
  - `scope: '/conduite'`
  - `start_url: '/conduite'`
- Splash auto-généré par Android depuis manifest (pas d'images statiques)
- IndexedDB persistant (pas de purge agressive comme iOS)
- Background Sync API : supporté → utiliser quand disponible, fallback listener `online` sinon
- Web Push : disponible (mais reporté Phase 06)

## Inconnues techniques (7 questions discuss)

### Q1 — Server Actions vs Route Handlers pour mutations driver

✅ **TRANCHÉ discuss 2026-05-18 : Route Handlers explicites (Alt A) — DEC-045 LOCKED**

- Q1.1 Décision finale : **Route Handlers** `/api/driver/rides/[id]/start|end`
- Q1.2 Endpoint shape : `/api/driver/rides/[id]/start` + `/api/driver/rides/[id]/end` (REST classique)
- Q1.3 Auth : cookies Supabase (middleware déjà en place), pas de JWT séparé
- Q1.4 Schéma payload : JSON `{ idempotency_key: uuid, client_timestamp: iso8601, ...payload }`

Justification : visibilité explicite endpoints (curl-able), compatibilité Serwist offline cache standard, debugging device réel facilité, cohérence pattern REST. Server Actions via fetch headers `Next-Action` fonctionnent mais opaque pour debug offline + Serwist cache strategies plus complexes.

### Q4 — Sync engine : retry strategy

⏳ À AFFINER plan-phase (defaults proposés discuss)

- Q4.1 Essais max : **3** pour V1 (cohérent baseline). Si UAT terrain révèle taux dead letter > 5% en zone Hauts, escalade à 5 essais en hotfix-bis.
- Q4.2 Dead letter UX : toast Sonner destructive + log `audit_logs` (catégorie `sync_dead_letter`). Visibilité régulatrice cockpit reportée Phase 05 (intégration cockpit temps réel).
- Q4.3 Ordering mutations : **FIFO strict par ride_id** (start avant end même course). Mutations sur rides différents parallélisables côté Route Handler (idempotency_key serveur dédup).
- Q4.4 Idempotency : UUID client-side généré au moment de l'action (Dexie stocké), serveur dédup via colonne `idempotency_key` unique sur table `ride_events` (à valider plan-phase, migration possible Wave 3).

### Q5 — ConnectionStatus header : 4 cas UX

⏳ À AFFINER ui-phase (esquisse discuss)

- Q5.1 UI 4 cas :
  - `online idle` : badge vert discret, icône wifi, pas de texte (header minimal)
  - `synching` : badge bleu, icône sync animée (rotation), texte « Synchronisation… N mutation(s) »
  - `offline + queue` : badge orange, icône wifi barré, texte « Hors-ligne · N en attente »
  - `offline idle` : badge gris, icône wifi barré, texte « Hors-ligne »
- Q5.2 `synching` trigger : automatique quand `pendingCount > 0 && online` (pas de swipe-down manuel — pattern automatique standard 2026).
- Q5.3 Position : top fixed, hauteur 32px, sticky sous header app. Non intrusif mais toujours visible.
- Q5.4 Realtime Supabase : actif en `online idle` (data freshness), pausé quand pendingCount > 0 pour économiser bande passante pendant le flush.

## Risques identifiés

1. **iOS purge IndexedDB ~2 semaines** d'inactivité (DEC-022 mitigation `navigator.storage.persist()` + warning UI 7j). Risque résiduel : chauffeur qui n'utilise pas la PWA 14+j perd ses mutations en attente. Acceptable car queue dead letter dans audit_logs côté serveur si dernière sync OK.
2. **3G/4G zone Hauts intermittent** (Q4.1 retry 3 essais). Mitigation : si taux dead letter > 5% en UAT, escalade 5 essais hotfix-bis. Pas bloquant V1.5.
3. **PWA install rejeté Safari iOS si manifest invalide**. Mitigation : test rigoureux Wave 6 sur device réel, lint manifest via Chrome DevTools Application > Manifest.
4. **Background sync non supporté iOS** (confirmé recherche). Fallback `online` listener fonctionne mais ne déclenche pas si app fermée. Acceptable V1 (chauffeur ouvre app au début/fin tournée).
5. **Cookies Supabase auth perdus si IndexedDB purgé** (iOS 2 semaines). Re-auth flow : redirect `/login` standard, mais chauffeur perd contexte tournée. Mitigation `navigator.storage.persist()` + warning 7j.
6. **Server Actions vs Route Handlers** compatibility Serwist offline cache : Route Handlers Alt A retenu (DEC-045) car cache strategy `NetworkOnly` + queue offline plus simple à implémenter qu'avec Server Actions opaques.

## Success Criteria (8 critères validés discuss)

1. PWA installable propre **iPhone + Android** (icônes nettes, splash, theme_color cohérent, Option A cross-platform)
2. Démarrer + clôturer course en mode avion, mutation sync au retour réseau, `audit_logs` cohérent
3. `ConnectionStatus` affiche les 4 états distinctement (test Playwright assertions)
4. Warning UI > 7 j inactivité visible au prochain mount PWA
5. Dead letter queue toast Sonner après 3 échecs de retry
6. **Idempotency** : mutation rejouée ne duplique pas en BDD (UUID client-side + serveur dédup colonne `idempotency_key` unique)
7. **UAT informel pré-démo** : checklist 5-10 min PWA + offline validée par dirigeant sur **2 devices réels** (iPhone + Android)
8. **Audit logs cohérents** : mutations offline ont `user_id` + `client_timestamp` respectés (pas overwritten par server timestamp seul)
