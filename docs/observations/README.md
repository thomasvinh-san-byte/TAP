# Observations terrain

Notes d'immersion auprès des design partners (sociétés TAP et taxiteurs conventionnés CGSS de La Réunion).

## Pourquoi ce dossier

Le pilier 1 du projet est l'UX qui donne envie d'être utilisée 8 heures par jour. Cela impose de **voir le métier en vrai**, pas de l'imaginer. Toute observation de terrain — journée passée avec une régulatrice, run en double avec un chauffeur, point avec un dirigeant — est consignée ici.

## Format

Un fichier par session d'observation, nommé `AAAA-MM-JJ-societe-role.md`.

Squelette recommandé :

```markdown
# Observation — AAAA-MM-JJ — Société X — Régulatrice

- **Durée** : 4 heures
- **Personne observée** : Sandrine, régulatrice (12 ans d'expérience)
- **Contexte** : matinée standard, pic d'appels 7h-9h

## Ce que j'ai vu
- Faits bruts, dans l'ordre

## Ce qui marche aujourd'hui
- Habitudes, raccourcis informels, post-it, fichiers Excel persos

## Ce qui ne marche pas
- Frictions, double saisie, erreurs récurrentes, contournements

## Verbatim marquants
- Citations exactes, jamais reformulées

## Implications produit
- Modules CDC concernés, hypothèses à tester
```

## Confidentialité

- Pas de nom de patient, pas de NIR, pas d'adresse exacte dans ces fichiers
- Anonymiser les données opérationnelles citées (remplacer par "Patient A", "Adresse X")
- Si une observation contient un détail sensible, la stocker hors dépôt
